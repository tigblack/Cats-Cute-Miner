Cats Cute Miner runtime integration handoff

Resources/Integrations/cats-cute-miner-sdk.json holds this game's public client configuration. Own Meta/rewarded and Adjust registrations exist. User deferred MAX for the first release; published game-specific legal URLs are still pending. Current external state and authorization are in release/google-play/profile.json. Management credentials and upload signing passwords must never enter this asset.

Android GameBootstrap presents NeutralAgeFlow before the game or any SDK consumer starts. Unknown, skipped, corrupt/unselected age and all under-16 categories are protected. All four collectors stay off; MAX/Meta are never called for protected users. The coarse installation-level age record survives campaign resets; no DOB is stored. Older users have independently optional provider choices, initially off. Settings allows choices to be revisited without changing the age category. Analytics revocation disables AppMetrica sending and Adjust; selected Meta event calls and future ads stop. SDKs already initialized cannot be unloaded; changing age after init is therefore not offered.

Parent-owned native configuration requirements:
- Explicit effective Meta manifest AutoInitEnabled, AutoLogAppEventsEnabled and AdvertiserIDCollectionEnabled=false. Runtime verifies metadata before consented Meta init; child protection also requires the merged manifest to retain these flags before managed code starts.
- MAX ProjectSettings/AppLovinInternalSettings.json: enabled native consent flow and exact game-specific policy/terms URLs, no debug geography. MAX AppLovinSettings SDK key must match own runtime key. Runtime reads the generated Android raw applovin_settings JSON before MAX init and requires supported CMP and actual IsUserConsentSet after init, without SetHasUserConsent(true).
- AppMetricaSettings.xml Feature.AppLovinAdRevenueV8.Enabled=False and no APPMETRICA_FEATURES_ADREVENUE_APPLOVIN_V8 scripting symbol. Native RevenueAutoTrackingEnabled=false disables automatic IAP reporting, NOT the Unity automatic MAX handler. Runtime refuses AppMetrica activation while that handler is compiled; the release gate checks both settings and symbols.
- Confirm native SDK versions/resolution, vendor plugin importers, own registrations/package/key hashes, game legal content and geographic consent scope with release artifacts and a real device. Local key shape/config binding cannot prove remote ownership or delivery.

Direct pinned API sources reviewed: AppMetrica v6.7.0 AppMetrica/AppMetricaConfig/AdRevenue and automatic MAX handler; Adjust v5.8.1 Adjust/AdjustConfig/AdjustAdRevenue; MAX UPM8.4.2 MaxSdkAndroid/MaxSdkCallbacks/MaxCmpService/AppLovinPostProcessAndroid; official Meta sdk-version-18.1.1 FB.cs. Runtime calls these APIs directly; no reflection/mock SDK bridge.

Outpost persists each offered placement/amount/run before ShowRewardedAd. Only a matched earned callback prepares the reward and replay ledger atomically. Delivery survives controller recreation in the same process, offline catch-up and retry of the same save snapshot; no wall-time timeout cancels a long/background show. SDK callbacks are marshalled to the main thread. ILRD tracks one impression per unique show placement, independently once per configured recipient, including late revenue after hidden. Close/error/revenue callbacks do not grant. Missing-placement failures cannot safely be associated by ad unit alone: the offer is quarantined until an explicit player retry; a retry abandons the unresolved show without granting. Device QA must verify placement propagation and callback ordering. A very late reward for an abandoned/overwritten offer fails closed. If storage refuses every write and the process is killed before the earned/grant snapshot is durable, an in-memory callback cannot be recovered.
