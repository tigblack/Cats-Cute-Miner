# Cat Miners — руководство по пиксельному стилю

Утверждённый стиль: **пиксель-арт** по концепту [`Concepts/style-exploration-2026-10-06/04_pixel_art.png`](Concepts/style-exploration-2026-10-06/04_pixel_art.png), решение от 6 октября 2026 года.
Документ обязателен для всего нового визуала: поле, персонажи, интерфейс, обучение, будущие фичи. Если что-то здесь не описано, ориентир — концепт. Новый элемент должен выглядеть так, будто он всегда был на этом экране.

Отличия от концепта, обязательные для игры:
- **Ширина поля всегда 7 клеток.** Это максимум, на концепте показано 5.
- **Перед игроком всегда два свободных ряда по 7 клеток — зона мержа котиков.** Это два полностью свободных ряда площадки появления: над кузницей на старте, над воротами после их открытия (ТЗ 6.4, 6.6). Пустые клетки этих рядов помечаются пунктирным «+» (`slot_marker`), как ячейки на концепте.
- Кузница — объект 2×3 на поле (по данным 2×2, расширена на строку вниз, ТЗ 6.4), а не декорация у стены. Это «кошачья печь» из рыжего кирпича: яркое пятно внизу экрана.
- У правого края поля, сразу под зоной мержа, стоит пушка (1×2) и смотрит влево: из неё вылетают бочки с котиками — нанятыми и бесплатными (ТЗ 7.2).

## 1. Масштаб и техника

| Параметр | Значение |
|---|---|
| Пикселей арта на клетку поля | **32** (`PixelArt.CellPixels`) |
| Интерфейс | 1 пиксель арта = **4** единицы Canvas при эталоне 1080×1920 (`PixelArt.UiPixel`) |
| Фильтрация | Point, без мип-мапов, без сглаживания |
| Камера | ортографическая, **строго сверху** (наклон 90°); объекты нарисованы в виде 3/4 |
| Поворот спрайтов | запрещён (кроме отражения по X). Вращение рисуется кадрами |
| Масштабирование | только целое; исключение — короткие «поп»-анимации не дольше 0,25 с |
| Полупрозрачность | только тени, свечение, затемнение секторов (`alpha=True` в генераторе) |

Все спрайты рисуются кодом в `Tools/PixelArt/sprites/*.py` (библиотека `Tools/PixelArt/pxl.py`). `Tools/PixelArt/build.py` упаковывает их в один атлас и пишет `Assets/Game/Scripts/Runtime/Pixel/PixelAtlasData.g.cs` — PNG в base64. PNG-файлы не синхронизируются хабом, поэтому атлас встроен в код. Unity получает спрайты только по имени: `PixelArt.World("rock_plain_0")` для мира, `PixelArt.Ui("ui_btn_gold")` для интерфейса. Список обязательных имён — `Tools/PixelArt/manifest.py`.

## 2. Палитра

Единственный источник цветов — `RAMPS` в `pxl.py`. Сборка отклоняет пиксель вне палитры. Рампы идут от тёмного к светлому.

| Рампа | Где используется |
|---|---|
| `ink` | контуры, самые глубокие тени |
| `navy` | камень пещеры, стены, тёмные панели UI |
| `slate` | плиты пола |
| `stone` | добываемые камни |
| `wood` | опоры, ворота, ящики, таблички, деревянные панели UI |
| `amber` | огонь, фонари, тёплый свет |
| `gold` | монеты, самородки, главная кнопка, акценты |
| `purple` | эликсир, аметисты, кристаллы на стенах |
| `teal` | самоцветы (твёрдая валюта) |
| `blue` | комбинезоны, вода, синие кнопки |
| `red` | динамит, крыши, опасность, уведомления |
| `green` | мох, зелёные кнопки, «готово» |
| `pink` | носы, ушки, щёки |
| `cream` | текст, блики, мордочки |
| `fur_*` | окрасы котиков (6 вариантов по 5 тонов); `fur_ginger` — ещё и блестящая медь шестерён и труб |
| `cave`, `frost` | кристальная пещера: камень стен и препятствий, плиты пола |
| `copper`, `rust` | медная выработка: порода стен и препятствий, плиты пола |

Настроение — тёплый свет построек и фонарей на холодном синем камне. Холодные тона занимают фон и большие площади. Тёплые — точки интереса: огонь, золото, фонари, кнопки действия.

## 3. Свет, контур, объём

- Свет падает **сверху-слева**: блик на верхней и левой гранях, тень — на нижней и правой.
- Внешний контур 1 px берётся из самого тёмного тона рампы материала или из `ink1`/`ink2`; чисто чёрный не используется. Внутренние линии на один тон темнее заливки.
- На материал — 3–5 тонов. Тени уводятся в холодное (navy/purple), блики — в тёплое (amber/cream).
- Дизеринг — только упорядоченный (`Canvas.dither`) и только на крупных плоскостях: стены, ореолы. Случайный шум даёт `Canvas.speckle` с плотностью не выше 0,08.
- Каждый объект на поле получает мягкую овальную тень `shadow_*`: alpha около 35 %, цвет `ink0`.

## 4. Поле (мир)

**Координаты.** Клетка (column, row) → мир (x = column + 0.5, z = Depth − row − 0.5). Строка 0 — верх карты. Мировая +Z — «вверх по экрану». Камера смотрит вниз по −Y. Визуальная «высота» объекта рисуется в спрайте и не задаётся смещением по Y.

**Узел визуала.** `PixelWorld.Visual(root)` создаёт дочерний узел, повёрнутый к камере. В нём X направлена вправо, Y — вверх по экрану, единица — клетка. Спрайт ставится через `PixelWorld.Sprite(visual, name, sprite, pos, order)`.

**Pivot «ноги».** Нижний центр холста совпадает с нижней кромкой footprint объекта: x = column + W/2, z = Depth − row − 1, где row — строка якоря. Холст шириной W·32 может подниматься выше footprint и перекрывать ряд над объектом:
- камни — до 8 px;
- одиночные препятствия — до 8 px;
- столбы ворот (`wall_gate_*`) — до 24 px;
- кузница — до 10 px: сразу над ней зона мержа, туда заходят только кончики ушей и короткая труба;
- пушка — до 8 px: дульный срез остаётся под зоной мержа;
- шахта — до 16 px;
- ворота — до 32 px;
- выход — до 48 px, над ним задняя стена.

**Кристаллы, самородки и цветные жетоны** на клетках поля бывают только у добываемых камней (`rock_*`). Препятствия (`block_*`) рисуются из камня `navy` с мхом, грибами и деревом. Кристаллы вне камней — только декор стен (`crystal_cluster_*`). Иначе игрок не отличит цель добычи от препятствия.

**Наложения** (колесо копра, огонь, створки, трещины, каска, оружие) рисуются на холсте того же размера, что и база, и регистрируются с тем же pivot. Сборка сама обрезает пустые поля.

**Порядок отрисовки** задаётся явно, в `PixelWorld`:

| Слой | Порядок |
|---|---|
| пол и стены (меш атласа) | `FloorOrder` |
| разметка зоны мержа | `FloorDecalOrder` |
| объекты и котики (`SortingGroup` на корне) | `OrderAt(z опоры)`: ниже на экране — позже |
| затемнение закрытых секторов | нижний закрытый сектор и сектор, который сейчас открывается, — `OrderAt(нижняя кромка сектора) + OrderPerCell / 2`, поэтому ворота под ним остаются светлыми; остальные закрытые — `FogOrder` |
| частицы | `FxOrder` |
| полосы HP, бейджи, пузыри статуса, подписи | `OverlayOrderAt(z)` |

**Ореолы фонарей:** у фонарей на опорах — узкий `fx_glow_lantern`, целиком на стене; у фонарей задней стены — `fx_glow_warm`.

**Закрытые секторы** закрываются полупрозрачным тёмным прямоугольником (`px_white`, «цвет глубины» оформления `PixelTheme.Dark` — `navy0` в штольне, alpha около 0,62) поверх объектов сектора. Открытие сектора — плавное исчезновение затемнения за 0,8 с. Белой вспышки нет.

**Размеры объектов**

| Объект | Footprint | Холст | Спрайты |
|---|---|---|---|
| камень | 1×1 | 32×40 | `rock_*`, трещины `rock_crack_1/2` |
| препятствие | по данным | 32×32 на клетку (автотайлы) или 32×40 (одиночные) | `block_*`, `waterfall_*` |
| столбы ворот | 1×1 (`wall1x1vL/vR`) | 32×56, ноги (16, 0) | `wall_gate_l`, `wall_gate_r`: стоят по краям строки ворот и стыкуются с крайними столбами забора `gate_frame` на всю его высоту |
| шахта | 2×3 | 64×112 | `shaft_base` + наложения |
| ворота | 5×1 | 160×64 | `gate_frame` + `gate_door_*` |
| выход | 3×1 | 96×80 | `exit_base` + `exit_boards` / `exit_glow` |
| кузница | 2×3 (`row_c − 1 … row_c + 1`) | 64×106, ноги (32, 0) | `forge_base` — «кошачья печь»: голова рыжего полосатого кота из кирпича (`fur_ginger*`), розовые уши, полоски «М» на лбу, бирюзовые глаза-окошки со щелью зрачка, нос, усы, топка в каменной арке — открытый рот, синий ошейник с золотыми заклёпками и колокольчиком; во дворе наковальня на пне с золотой лапкой, золотые слитки, золотая кошка-талисман на красной подушке. `forge_fire_*` — огонь и отблеск в глазах, `forge_glow` — ореол топки. Устье трубы — (32, 2) холста (`ObjectView.ForgeChimneyPixel`) |
| пушка | 1×2 у правого края, `(6, row_c − 1 … row_c)` (клетки закреплены за кузницей, не объект данных) | 32×72, ноги (16, 0) | `cannon_base` (лафет, хобот, дальнее колесо) + `cannon_barrel` (ствол, слой отдачи) + `cannon_wheel_0/1` (ближнее колесо поверх ствола); ствол ≈48° вверх-вправо, в игре пушка отражена по X и смотрит влево; центр дульного среза — (26,5; 33,5) холста (`CannonView.MuzzleCanvas`) |
| контейнер | 1×1 | 32×36 | `barrel_cat`, `crate_*`; в полёте из пушки — `barrel_fly_0/1` (котик зажмурился и машет лапками) |
| котик | 1×1 | 40×40, ноги (20, 4) | `cat_body_*` + `cat_helmet_*` + `cat_pick_*` |

**Стены.** Слева и справа от поля видно около 0,65 клетки стены: камень пещеры, деревянные опоры, фонари, кристаллы, знамёна. Декор стоит только на стенах и в клетки поля не заходит. Сверху — задняя стена штольни, снизу — грунт.

**Оформления окружения** (`Docs/Visual/ART_DIRECTION.md`, раздел 6). Тёплая штольня — базовый арт. Кристальная пещера и медная выработка — перекраска `Tools/PixelArt/sprites/themes.py`: варианты `<имя>_crystal` и `<имя>_copper` для пола, стен, углов, кромок, порога ворот, препятствий, столбов ворот, водопадов, скальных частей шахты и выхода, декора стен с камнем. Камни добычи, постройки, котики и UI не перекрашиваются. В Unity имя спрайта поля проходит через `PixelTheme.Name`: вариант темы берётся, если он есть в атласе. Свои детали тем: `crystal_spire` (высокая друза), `gear_copper_0…7` (шестерня, 0,2 с/кадр, пары крутятся навстречу), `pipe_copper`. Ореолы друз — `fx_glow_purple` / `fx_glow_teal` / `fx_glow_blue`. Фон камеры и затемнение секторов — `PixelTheme.Dark` (`navy0` / `cave0` / `copper0`). Диапазоны зон — `Assets/Game/Resources/Visual/environment_themes.json`.

**Повреждение камней.** Три стадии `<камень>_d1…d3` у каждого основного камня (доля HP < 0,75 / < 0,45 / < 0,2): силуэт теряет куски, появляются трещины, щели и камешки у основания. Если стадии нет, используется прежнее наложение трещин `rock_crack_1/2`.

**Состояния шахты** — наложения того же холста 64×112: `shaft_rubble` (завал), `shaft_ribbon` (готова к активации), `shaft_light` + `shaft_wheel_*` (работает), `shaft_heap` (тонируется цветом самоцвета) + `shaft_glint_0…3` (готова выплата), `shaft_plaque` (автоматизирована).

## 5. Котики

Подробно — `Docs/Visual/ART_DIRECTION.md`, раздел 4. Код: `Tools/PixelArt/sprites/cats.py` (оснастка тела и каски), `Tools/PixelArt/sprites/weapons.py` (оружие), `CatLook` (имена кадров, окрас, оружие, цвет каски), `CatView` (машина состояний кадров).

- **Слои** (снизу вверх): тень `shadow_s` → тело `cat_body_<окрас>_<кадр>` → каска `cat_helmet_<цвет>_<кадр>` → оружие `cat_weapon_<оружие>_<кадр>`. Все слои — холст 40×40 с pivot (20, 4). Котик нарисован смотрящим вправо; влево — `flipX` у всех слоёв.
- **Окрас** — по id котика (`CatLook.Coat`): `ginger, gray, black, white, cream, brown`, у каждого свои отметины: полоски, манишка, проточина, пятна калико, тёмные «пойнты».
- **Уровень** читается тремя способами:
  - бейдж `badge_level` с цифрами `digit_*` справа снизу — главный носитель, работает для любого уровня;
  - оружие — по кругу из 8 уровней (`CatLook.Weapon`): `pick` кирка, `hammer` молот, `crusher` дробилка, `saw` циркулярная пила, `drill` бур-машина, `dualpick` две кирки, `chainsaw` бензопила, `laser` лазерган; у каждого свой звук удара;
  - цвет каски — номер круга (`CatLook.HelmetColor`): жёлтый (1–8), синий, красный, зелёный, фиолетовый, бирюзовый, розовый, белый, дальше по кругу.
- **Оружие рисуется кодом** по оси кадра `Pose.pick` (торец рукояти → верх): формы задаются в координатах вдоль оси и поперёк, свет — сверху-слева по экрану, общий контур `ink1`, лапки вырезаются. Инструменты (`saw`, `drill`, `chainsaw`, `laser`) добывают «с упора» — кадрами `tool_*`; у них в кадрах `tool_strike`/`tool_impact` свой эффект (искры, пыль, вспышка излучателя). Кадров, которые оружие не показывает (`mine_*` у инструмента, `tool_*` у ударного), в атласе нет.
- **Кадры** (`manifest.CAT_FRAMES`, 62 на слой):

| Кадры | Назначение | Темп |
|---|---|---|
| `idle0…5`, `blink`, `blink_d` | дыхание; моргание раз в 2–5 с | 0,22 с |
| `stretch0…9` | редкое потягивание с зевком, раз в 10–26 с | 0,12 с |
| `walk0…7` | ходьба: смена опорных лап, оружие в лапках | 0,09 с |
| `mine_ready`, `mine_ready2`, `mine_antic`, `mine_raise`, `mine_top`, `mine_strike`, `mine_impact`, `mine_recoil`, `mine_return` | добыча замахом (кирка, молот, дробилка, две кирки): готовность → подготовка → замах → удар → отдача → возврат; фаза замаха — по времени до удара, удар — по событию `TargetHit` | по симуляции |
| `tool_ready` … `tool_return` (те же 9 фаз) | добыча с упора (пила, бур, бензопила, лазер): инструмент перед собой → оттянул → прицелился → подал вперёд → упёрся → отдача → стойка; `CatLook.ForWeapon` подменяет фазы `mine_*` | по симуляции |
| `drag0…3` | котика несут: лапки и хвост болтаются | 0,11 с |
| `spawn0…7` | появление: присел, прыжок, приземлился, оглядывается | по таблице `CatView` |
| `joy0…5` | радость: прыжок с поднятыми лапками | по таблице `CatView` |

- При переносе кандидаты на объединение (тот же уровень) получают `badge_level_hi`. Клетка, куда котик встанет, подсвечивается `slot_marker_hi` (красным — если туда нельзя). Выделение котика — `select_ring` под ним.

## 6. Интерфейс

Интерфейс собирается только из UI-кита: `PixelUi` (`Assets/Game/Scripts/Runtime/UI/PixelUi.cs`), `UiFonts`, `TutorialHint`. Это касается всех окон, подсказок обучения и новых фич. Свои цвета, формы и шрифты в обход кита не заводятся. Старый API `Ui.Panel/Button/Icon` (Palette-цвета) оставлен для совместимости и рисуется тем же китом. Новый код его не использует.

### 6.1. Сетка, шрифт, цвета

- **Сетка.** 1 пиксель арта = `PixelUi.Px` = 4 единицы Canvas при эталоне 1080×1920. Размеры и отступы кратны 4, позиции округляются через `PixelUi.Snap`. Иконки масштабируются только в целое число раз.
- **Шрифт** — Pixeloid Sans (SIL OFL, GGBotNet; `Assets/Game/Resources/Fonts/PixeloidSans-Regular.ttf` и `-Bold.ttf`, лицензия `PixeloidSans-OFL.txt` рядом). Выбран пользователем 12 октября 2026 по листу сравнения `Docs/Reports/font-candidates/font-comparison.png` вместо Tiny5: у Tiny5 заглавные 5 пикселей, строчные 4, и текст не читался. У Pixeloid заглавные 7 пикселей, строчные 5, есть латиница, кириллица и настоящее жирное начертание:
  - `UiFonts.Default` — текст;
  - `UiFonts.Bold` — заголовки, кнопки, числа (Pixeloid Sans Bold, без искусственного утолщения).

  Другие кандидаты листа: Pixel Operator (тонкий, мелкие подписи бледные), Pixelify Sans (цифры 2 и 8 путаются на малом размере), DotGothic16 (точечный стиль не совпадает с артом). Tiny5 остаётся в `Resources/Fonts`, но игрой не используется. Пиксель Pixeloid равен 1/9 размера (`UiFonts.EmPixels`), поэтому берутся только размеры из таблицы — они кратны 9. Значения подобраны под прежние размеры Tiny5: высота заглавных и ширина строк почти не изменились. Автоподбор размера допустим только для длинных строк.

  | Константа | Размер | Пиксель шрифта | Где |
  |---|---|---|---|
  | `FontSmall` | 18 | 2 ед. | подписи, бейджи, пояснения |
  | `FontBody` | 27 | 3 ед. | основной текст, строки окон, подсказки обучения |
  | `FontLarge` | 36 | 4 ед. = 1 px арта | кнопки, числа HUD, заголовок окна (планка `PixelUi.Window`), заголовки панелей, текст экрана конца кампании |
  | `FontTitle` | 45 | 5 ед. | главные кнопки и крупные подписи: окно карточки, переход на следующую шахту, «Нанять» старого режима |
  | `FontHero` | 54 | 6 ед. | резерв, сейчас не используется; перед применением внести место в таблицу |
  | `FontHuge` | 72 | 8 ед. = 2 px арта | резерв, сейчас не используется; перед применением внести место в таблицу |

  Подписи на поле (`Label3D`): `SmallSize` = 2,8125 (пиксель шрифта = 1 пиксель арта), `LargeSize` = 5,625 для всплывающих наград (2 пикселя арта). Стрелка «→», «×», «·», «—» и «…» есть в Pixeloid; недостающие символы (★) берутся из fallback-шрифта TMP.
- **Тень.** Светлый текст на тёмном фоне получает пиксельную тень: `shadow: true` или `PixelUi.SetShadow`. Тень — цвет `ink1`, на 1 пиксель шрифта вниз, без размытия. Материал общий на шрифт, поэтому тексты батчатся. Тёмный текст тени не имеет.
- **Цвета текста:**
  - `TextColor` — `cream3`, основной;
  - `TextDim` — `cream1`, приглушённый и недоступный;
  - `TextAccent`/`TextAccentLight` — `gold3`/`gold4`, акцент и цены;
  - `TextDark` — `wood0`, на золотых кнопках, светлых панелях и пузырях;
  - `TextBad` — `red5`, `TextGood` — `green5`, `TextElixir` — `purple5`.

  Для части строки используются теги `DimTag`/`AccentTag`.
- **Затемнение** — `ShadeColor` (`ink0`, alpha 0,62).

`Ui.ButtonRefs` управляет кнопкой: `SetLabel`, `SetInteractable`, `SetStyle`, `SetIcon`, `SetBadge`, `SetActive`. Подпись и иконка лежат в `Content`. При нажатии `Content` опускается на 1 пиксель арта, а спрайт меняется на `_pressed`. Недоступная кнопка — `ui_btn_disabled` и тусклая подпись; у ячейки иконка приглушается. Клик играет `UiSound.Click`, тап по недоступной кнопке — `UiSound.Denied`.

### 6.3. Правила

- Состояние меняется только при смене значения: `SetText`, `SetValue`, `SetCount`, `SetInteractable`. В `Update` не создаются элементы, строки и коллекции.
- Панель ловит лучи UI: жест над ней не уходит на поле. Декоративным элементам ставится `raycastTarget = false`.
- Минимальный размер 9-slice — сумма двух border спрайта. Высота кнопки — `ButtonHeight` (28 px арта), кнопки в строке списка — `SmallButtonHeight` (20 px), ячейки — `SlotSize` (40 px).
- В ячейку `SlotSize` иконка `icon_*_big` ставится с `scale` 1. При `scale` 2 ячейка должна быть от 240 единиц.
- Анимации короткие и «пружинистые». Окно появляется за 0,15 с, масштаб 0,9 → 1 (`PixelPop`). Нажатие мгновенное. Плавных градиентов, размытия и скруглённых векторных форм нет.

### 6.4. Как собрать новое окно

```csharp
// HudShop.cs — окно «Магазин» (пример): public sealed partial class Hud { PixelWindow m_Shop; void BuildShop() { … } }
m_Shop = PixelUi.Window(m_Safe, "Shop", Loc.T("hud.shop.title"), () => m_Shop.Hide());
m_Shop.Box.Anchor(0.06f, 0.22f, 0.94f, 0.78f);                 // размер рамки
m_Shop.SetBody(Loc.T("hud.shop.body"));                         // или свои элементы в Body, тогда BodyText выключается
var row = PixelUi.Panel(m_Shop.Body, "row", PixelPanel.Inset);
m_Shop.AddButton("btn", Loc.T("hud.shop.buy"), PixelButton.Gold, Buy);
m_Shop.AddButton("btn", Loc.T("hud.shop.later"), PixelButton.Dark, () => m_Shop.Hide());
// при показе: m_Shop.Show();                                    // поверх соседей, звук открытия
```

- **Где живёт окно.** Новое окно — отдельный partial-файл `Hud<Фича>.cs` (как `HudWindows.cs`, `HudBlueprints.cs`). Окно строится от `m_Safe` методом `Build<Фича>()`, вызов которого стоит в `Hud.Build` после `BuildSettings()` и до `BuildModal()`: порядок детей SafeArea — порядок слоёв, модальное окно должно остаться сверху.
- **Ключи.** Тексты берутся только из `Loc`. Ключ имеет вид `<раздел>.<группа>.<имя>`, и префикс равен разделу файла `Loc.<Раздел>.cs`, который его регистрирует, иначе словарь сообщит об ошибке. Строки окон HUD — в `Loc.Hud.cs` как `hud.<окно>.*`.
- **Общих ключей нет.** Раздела `common` не существует. Ключи чужой фичи (например, `controller.next_mine.stay`) не заимствуются: у каждого окна свои `hud.<окно>.later`/`close`.
- **Новый раздел** нужен редко. Если нужен: файл `Loc.<Раздел>.cs` и три правки в `Loc.cs` — объявление `static partial void Register<Раздел>`, вызов `AddSection(…)` в `Build()` и запись в `Loc.Sections`.
- После добавления ключей `LocalizationTests` должны оставаться зелёными.
- Если кнопки включаются вручную, после этого вызывается `UpdateBodyArea()`.

### 6.5. Обучение

`TutorialHint` устроен как в эталоне (Gold & Goblins): наставник с репликой, лапка у цели.
- **Наставник** — рамка `ui_portrait_frame` (×1) с котом `tutor_cat_0` внутри. После новой реплики 1,2 с чередуются `tutor_cat_1`/`tutor_cat_0` по 0,15 с (говорит), дальше раз в 3–5 с на 0,12 с — `tutor_cat_2` (моргает). Нет спрайтов в атласе — остаётся один пузырь.
- **Пузырь** `ui_bubble` справа от портрета: тёмный текст `FontBody` по центру, ширина до 190 px арта (вместе с портретом — не шире safe area), низ на 40 % высоты портрета. Хвостик `ui_bubble_tail` у левого нижнего угла смотрит вниз, к наставнику (отражён по X).
- **Лапка** `icon_hand_big` ×2 касается цели кончиком пальца (пиксель (2, 2) холста) и нажимает: кадры по 0,1 с, отступ 2–1–0 пикселей спрайта по диагонали, касание 0,2 с с масштабом 0,9. У правого края лапка отражается по X, у нижнего края касается цели выше центра, чтобы не уйти за safe area.
- **Рамка** — золотые уголки `ui_focus_frame` вокруг цели, «дышат» на пиксель за 0,4 с.

Портрет с пузырём — один блок по центру ширины: над целью, если она в нижней половине экрана, иначе под ней вместе с лапкой. Сначала блок ищет место между панелями HUD (`SetReserved(BottomUnits, TopUnits)` в `Hud.Build`), затем в пределах safe area; наружу не выходит. Без цели — на 62 % высоты.

Подсказка **никогда не ловит лучи UI**: `CanvasGroup.blocksRaycasts = false`, у всех частей `raycastTarget = false`. `Dim = true` — только визуальное затемнение `ShadeColor` вокруг цели (с запасом за края safe area); тап по полю и другим кнопкам проходит.

API:
- `Show(text, rect)` — элемент UI; `ShowWorld(text, world, cells)` — объект поля (центр и footprint в клетках, через главную камеру); `MoveWorld(world)` — указатель за движущейся целью.
- `ShowDrag(text, from, to[, toCells])` — жест переноса: 0,25 с лапка над котиком, 0,2 с нажимает, 0,9 с плавно ведёт к камню (по сетке пикселей), 0,2 с отпускает, 0,55 с пауза, повтор. Рамка — вокруг камня. `MoveDrag(from, to)` сдвигает концы без перестройки текста.
- `Hide()`, `Visible`, `Text`. Цели UI HUD регистрирует в `Hud.Build`: `RegisterTarget(TutorialHint.TargetHire, rect)`, имена — константы `Target*`.

Как добавить шаг:
1. Реплика — ключ `tutorial.hint.<имя>` в `Loc.Tutorial.cs`: от лица наставника, коротко, одно действие.
2. Засчёт — в начале `TutorialController.Evaluate`, по состоянию: `if (!Done("tN") && условие) Complete("tN")`, чтобы уже выполненный шаг засчитывался сразу. По событию симуляции — дополнительно в `OnEvent`.
3. Подсказка — в блоке своей зоны, по порядку шагов: `return AtUi(Loc.T("tutorial.hint.x"), TutorialHint.TargetX)` (третий аргумент `true` — затемнение), `AtObject(text, ordinal)`, `AtCell(text, cell)` или `AtDrag(text, fromCell, toOrdinal)`. Покупку без ресурсов не предлагать (`CanHire() == CommandResult.Ok` и т. п.).
4. Остальное делает контроллер: перестраивает подсказку только при смене текста, цели или затемнения, ведёт указатель за целью и прячет подсказку под окнами, «Чертежами» и экраном конца кампании.

Шаги zone1: `t1` «Нанять» с затемнением → `t1b` бочка найма → `t2` перенос котика на ближайший доступный камень → `t2b` добыча с камня (иконки летят к счётчику — `Hud.FlyLoot`) → `t3` второй котик; дальше `t4`… Пока не было объединения, подсказка ведёт и к следующим бочкам найма.

### 6.6. Раскладка HUD

Код — `Hud.cs` (верх, низ, тост), `HudContext.cs` (контекстная панель), `HudWindows.cs` (окна, настройки, конец кампании), `HudBlueprints.cs` («Чертежи»). Размеры — единицы Canvas при эталоне 1080×1920, кратны 4. CanvasScaler с match 0,5 делает Canvas на экране 20:9 шириной около 966 единиц, поэтому по ширине раскладка тянется якорями, а высоты фиксированы. Отступ от краёв safe area — 8.

- `TopInset`/`BottomInset` считаются из этих высот и настоящей высоты safe area. Камера, ввод и стрелки у краёв считают поле между ними. Высота полосы меняется только константой в `Hud.cs`, тогда доли пересчитываются сами.
- Новый постоянный элемент HUD встаёт в верхнюю полосу или в нижнюю часть. Поверх поля допустимы только временные элементы: тост, кнопка перехода, контекстная панель.
- Элементы, на которые указывает обучение, регистрируются в `Hud.Build`: `hire`, `blueprints`, `dynamite`, `chests`, `free_cat` (плашка), `next_mine`, `context_action` (`ctx0`).

Движение по полю снапится к сетке 1/32 клетки (`PixelWorld.Snap`), чтобы спрайты не «дрожали».

**Выстрел пушки** (`CannonView.Fire`, ТЗ 7.2): отдача — вся пушка на 1 пиксель арта назад от цели, ствол ещё на 2 вдоль оси, колесо — кадр `cannon_wheel_1`; откат за 0,06 с, возврат за 0,32 с, целыми пикселями. Вспышка `fx_muzzle_*` — на 4 пикселя впереди дульного среза, затем два клуба `fx_smoke`; пыль `fx_puff` из-под колёс.

**Полёт бочки** (`ContainerView.Launch`): от дула дугой в клетку за 0,55–1,1 с, высота дуги 1,5–3,2 клетки (растут с расстоянием). Вылет — «поп» 0,6 → 1 за 0,12 с; летящая бочка рисуется с порядком `FogOrder + 1` (поверх поля, под частицами); тень на полу — `shadow_s`, а когда бочка выше клетки — `shadow_xs`. Приземление — сплющивание 1,25×0,78 → 0,92×1,1 → 1 за 0,18 с и `fx_puff`.

## 8. Звук

Звуки действий — мягкие и казуальные, без резких тонов: часть — записанные сэмплы CC0, часть синтезирована кодом (`Docs/Audio/build_sfx.py`). Музыка и атмосфера — оригинальные, синтезированы кодом (`Tools/Audio`). Список, лицензии, группы громкости — `Docs/Audio/SOUNDS.md`.

## 9. Как добавить новый элемент

1. Нарисовать спрайт в подходящем модуле `Tools/PixelArt/sprites/*.py` (или в новом, добавив его в `MODULES` в `build.py`).
2. Если код обращается к спрайту по имени — внести имя в `manifest.py`.
3. `python3 Tools/PixelArt/build.py`: проверка палитры и прозрачности, превью `out/sheet_<группа>.png`, атлас, `PixelAtlasData.g.cs`.
4. В Unity использовать только `PixelArt.World/Ui`, `PixelWorld.*` и компоненты `PixelUi`.
