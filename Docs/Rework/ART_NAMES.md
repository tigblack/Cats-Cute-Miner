# Новый арт режима CatOutpostV2: имена, размеры, раскладка

Справочник для `OutpostLook`, `OutpostCatView`, `BaseCampView`, `CargoPileView`, `GateBarrierView`, `OutpostTargetView`,
`FactoryView`, `PipeNetworkView` и `OutpostHud` (`Docs/Rework/RUNTIME_SPEC.md`, `VIEW_API.md`). Правила ТЗ —
`Docs/TZ/Cat_Miners_Auto_Incremental_TZ_v2.1.md` §5, §7, §8, §10, §16; заводы — `Docs/TZ/Cat_Miners_Factories_TZ_v2.2.md` §4–§6, §11.
Стиль — `Docs/Art/PIXEL_STYLE_GUIDE.md`. Конвейер — `Docs/Rework/map/art-audio.md` §2–§3.

Источник истины по именам — `Tools/PixelArt/manifest.py` (`REQUIRED`) и `Tools/PixelArt/out/manifest.json` (после полной сборки).
Все спрайты — код в `Tools/PixelArt/sprites/*.py`. Они упакованы в общий атлас `Assets/Game/Scripts/Runtime/Pixel/PixelAtlasData.g.cs`.
Unity берёт их по имени: `PixelArt.World(name)`, `PixelArt.Ui(name)`, `PixelWorld.Sprite(...)`.
Если имени нет, Unity показывает розовую заглушку и пишет одно предупреждение.

## 1. Общие правила

- **Pivot** — в пикселях от **левого нижнего** угла холста (как в Unity). Сборка обрезает пустые поля и пересчитывает pivot,
  поэтому в `manifest.json` он может быть отрицательным (например, `gate_barrier_mid` → (16, −9)). Положение в мире от этого не
  меняется. В таблицах ниже — **холст до обрезки** и его pivot.
- 1 клетка = 32 px арта = 1 юнит. Центр клетки: `CellCenter(c, r) = (c + 0.5, 0, Depth − r − 0.5)` (RUNTIME_SPEC §4.1).
- «Ноги (w/2, 0)» = нижний центр холста. Для построек это нижняя кромка footprint, для тайлов-«ног» — нижняя кромка клетки.
- Тайлы с `extrude` не обрезаются: холст 32×32, pivot (16, 16) или (16, 0), как указано.
- Варианты тем: для имён с пометкой «тема» есть `<имя>_crystal` и `<имя>_copper`. Брать через `PixelTheme.Name(name)`.

их не использует, вместо них — `cat_hat_*` / `cat_pick_*`. Продлевать их на новые кадры не нужно.

### 3.2 Раскладка (9 столбцов, ТЗ 2.2 §6.1)

Источник раскладки — `BaseCampView.Build`. Лагерь занимает девять центральных столбцов массива `b − 4 … b + 4`, где
`b = baseCol = Width / 2` (целочисленно) — столбец спавна и точки приёма `IntakeCell` (`MineTopologyAdapter`: площадка
`|col − b| ≤ 4`). Двор под площадкой той же ширины: в широких картах клетки строк лагеря и двора вне этих столбцов рисуются
породой (`OutpostBoardView.Topology`, `campRock`). Прежняя раскладка на 7 столбцов (0–6) — это `b = 3` без крайних
столбцов и без склада.

Обозначения:
- столбцы `b + k`, `k = −4 … +4`;
- строки площадки `pad0..pad2` = `Depth..Depth+2`;
- строки двора `st0..st2` = `Depth+3..Depth+5`;
- нижняя стена — `Depth+6`.

Координаты в Unity — по формуле §1: `x` — от левой кромки столбца 0 массива (центр столбца `b + k` — `x = b + k + 0.5`),
`z` — мировая.

```
k (столбец b+k):  −4     −3       −2     −1           0            +1           +2     +3     +4
pad0  z=-0.5      edge_t edge_t   edge_t edge_t       edge_t       edge_t       edge_t edge_t edge_t
pad1  z=-1.5      floor  floor    floor  SLOT         спавн        SLOT         floor  floor  floor      ← depot_slot в (b±1, D+1); спавн и IntakeCell — (b, D+1)
pad2  z=-2.5      edge_b edge_b   edge_b edge_b+chute edge_b       edge_b+chute edge_b edge_b edge_b     ← очередь котиков (без блокировки клеток)
st0   z=-3.5      ground ↑        ↑      ┌─────────────depot_base─────────────┐ ↑      ↑      ↑ inlet    ← верх построек 32×64; fpipe_inlet на коньке склада
st1   z=-4.5      ground WARDROBE HIRE   └────────────ноги x=b+0.5────────────┘ BENCH  RACK   WAREHOUSE  ← задний ряд: ноги на нижней кромке st1 (z = −5.0)
st2   z=-5.5      ground ground   SIGN   CRATE        ground       CRATE        CART   ground ground     ← передний ряд: ноги на нижней кромке st2 (z = −6.0 + 1 px)
D+6   z=-6.5      wall_bottom по девяти столбцам; вне b−4 … b+4 в строках лагеря и двора — порода (wall_top_*)
```

Столбец `b − 4` и передний ряд в `b − 3`, `b`, `b + 3`, `b + 4` свободны (земля двора). Ни одна постройка не поднимается выше
st0, поэтому очередь в pad2 ничем не закрыта. Новый котик выходит к спавну от точки (b − 1.5, −2.6) перед доской найма.

**Выбор тапом.** Общий коллайдер двора — `OutpostPickKind.Base` (центр (Width / 2, 0.4, −4.5), размер Width × 0.8 × 3): тап по
постройкам открывает «Базу». У склада свой коллайдер `OutpostPickKind.Warehouse` поверх общего (центр (b + 4.5, 0.45, −4.0),
размер 0.95 × 0.9 × 2), его приоритет выше `Base`: тап по складу открывает рынок. Трубы заводов приходят к `IntakeCell`
(b, D + 1); отрезок от неё до `fpipe_inlet` декоративный (ТЗ 2.2 §5). Точка «+N» прибытия товара и начала полёта монет продажи —
на 10 px выше центра `fpipe_inlet`.
Котики стоят ногами на `FeetY = −10 px` ниже центра клетки, как в `CatView`.

**Состояния (рекомендация, согласовано с RUNTIME_SPEC §4.3).**
- Ступень `t` постройки: 0 — уровень ветки < ⅓ cap, 1 — ≥ ⅓ cap, 2 — ≥ ⅔ cap. Ветки: доска найма — «Команда»; верстак — «Кирки»;
  стеллаж — «Сумки».
- Вагонетка: `cart_1`, когда ветка «Обувь» ≥ ⅓ cap.
- Ящики `depot_crate_0..3` — по доле доставленного груза шахты: 0, > 0, ≥ ⅓, ≥ ⅔.
- Шкаф: `wardrobe_open`, когда в коллекции есть ненадетые новые предметы.
- Место `n` занято (резерв или обслуживание) → `depot_slot_active`. Во время обслуживания → `depot_glow`.
- Склад товаров: `warehouse_full`, когда на складе есть товар (`FactoryQueries.AnyStock`), иначе `warehouse_empty`; при прибытии
  партии здание подпрыгивает на 1 px.

Хват / торец деревянной рукояти неподвижен во всех кадрах: пиксель (26, 15), то есть 16 px вправо и 13 px вверх от контакта.
В кадре 2 остриё касается pivot, в кадре 3 оно на 4 px выше. Поворот уже нарисован; код не вращает спрайты.
После обрезки атласом размеры и численные pivot могут различаться, но контакт и хват сохраняют положение в мире.

## 5а. Заводы, цепи, трубы, товары (ТЗ 2.2 §4, §5, §11; `sprites/factories.py`, `goods.py`, `fx.py`)

`<good>` — ID товара по номеру типа завода 1…20 (порядок `MineShafts` JSON и строк `Goods` в `factory_rules.json`, список
`GOODS` в `manifest.py`): `milk`, `wood`, `fish`, `yarn`, `catfood`, `boxes`, `bricks`, `steel`, `glass`, `catnip`, `toys`,
`scratchers`, `cushions`, `bells`, `collars`, `gears`, `lanterns`, `honey`, `silk`, `caviar`.

| Имя | Холст | Pivot | Использование |
|---|---|---|---|
| `factory_<good>` ×20 | 64×112 | (32, 0) | здание завода 2×3 на footprint `s`: силуэт копра `shaft_base` с колесом (колесо стоит), кровля и стены по заводу, вывеска с иконкой товара, двор с конвейером |
| `factory_<good>_work_0..3` | 64×112 | (32, 0) | наложение «работает» поверх здания: колесо крутится, дым из трубы, конвейер; 0,15 с на кадр; порядок здания + 1 |
| `factory_chains` | 64×112 | (32, 0) | цепи крест-накрест и большой замок поверх здания (Locked) |
| `factory_chains_crack_1..3` | 64×112 | (32, 0) | трещины звеньев и замка поверх цепей при HP цепей < 0,75 / 0,45 / 0,2 (пороги как у `shaft_crack_*`) |
| `fx_chain_break_0..3` | 32×32 | центр | разлёт звеньев и замка при открытии (`FactoryUnlocked`), 0,07 с на кадр |
| `fpipe_cap` | 14×14 | центр | заглушка трубы у завода: фланец с окном 8×8, поверх по центру — `goods_<good>_8` |
| `fpipe_coupling` | 12×12 | центр | муфта жгута труб |
| `fpipe_inlet` | 16×10 | центр | вход труб на склад (§3.2) |
| `fpipe_capsule` / `fpipe_capsule_h` | 3×6 / 6×3 | центр | партия в пути на вертикальной / горизонтальной трубе; белые тона, код красит цветом товара |
| `goods_<good>` ×20 | 16×16 | центр | иконка товара в UI: рынок, «Deliver ×N», стрелка у края экрана, «+N» |
| `goods_<good>_8` ×20 | 8×8 | центр | малая иконка товара: заглушка трубы, «+N» на поле |

Состояния завода (`OutpostTargetView`, `FactoryView`) собираются из слоёв одного холста и одного pivot:
- `Locked` — `factory_<good>`, затемнённый `SpriteRenderer.color` (≈ 0,45 / 0,45 / 0,55), поверх `factory_chains`, трещины и
  полоса HP цепей;
- `Working` — здание + `factory_<good>_work_0..3`, прогресс-бар цикла над зданием;
- `Ready` / `Stopped` — здание без наложения (колесо стоит). У `Ready` — полный бар и плавающая кнопка «Deliver ×N».

Ноги — нижняя кромка footprint, как у `shaft_base`. Заводы темами окружения не перекрашиваются (`_crystal`/`_copper` у них нет),
как постройки лагеря. Анимация работы общая для заводов с одним видом дыма: одинаковые кадры атлас хранит один раз.

**Трубы** (`PipeNetworkView`, ТЗ 2.2 §5) строит код вдоль маршрута один раз на шахту: толщина 3 px арта, тёмный контур и полоса
цвета товара. Цвет — `factory_rules.json → Goods[].Color` (тон палитры `pxl.py` вида `<рампа><индекс>`, например `cream4`), в
Unity — `PixelPalette.ByName`. k-я труба прохода смещена от стены на 4·k px; при тесноте трубы сводятся в жгут с муфтой
`fpipe_coupling`. Трубы лежат над полом и разметкой, под котиками, грузом и ещё не разрушенными целями; появляются при открытии
завода (прокладка до 1 с). На одной трубе видно не больше 3 капсул, пул капсул — 60. Префикс `fpipe_` не пересекается с декором
`pipe_copper`.

  проверить на устройстве (ТЗ §16).
- Фонари `camp_lantern_*` до ворот G3 стояли на краях массива (x = 0.5 и Width − 0.5): в широких картах (25–53 столбца) это порода
  далеко за девятью столбцами лагеря. С ворот G3 (15 октября 2026) `BaseCampView.Build` ставит их в передний ряд столбцов `b − 3` и
