# Новый арт режима CatOutpostV2: имена, размеры, раскладка

Справочник для `OutpostLook`, `OutpostCatView`, `BaseCampView`, `CargoPileView`, `GateBarrierView`, `OutpostTargetView` и
`OutpostHud` (`Docs/Rework/RUNTIME_SPEC.md`). Правила ТЗ — `Docs/TZ/Cat_Miners_Auto_Incremental_TZ_v2.1.md` §5, §7, §8, §10, §16.
Стиль — `Docs/Art/PIXEL_STYLE_GUIDE.md`. Конвейер — `Docs/Rework/map/art-audio.md` §2–§3.

Источник истины по именам — `Tools/PixelArt/manifest.py` (`REQUIRED`) и `Tools/PixelArt/out/manifest.json` (после полной сборки).
Все спрайты — код в `Tools/PixelArt/sprites/*.py`. Они упакованы в общий атлас `Assets/Game/Scripts/Runtime/Pixel/PixelAtlasData.g.cs`.
Unity берёт их по имени: `PixelArt.World(name)`, `PixelArt.Ui(name)`, `PixelWorld.Sprite(...)`.
Если имени нет, Unity показывает розовую заглушку и пишет одно предупреждение.

## 1. Общие правила

- **Pivot** — в пикселях от **левого нижнего** угла холста (как в Unity). Сборка обрезает пустые поля и пересчитывает pivot,
  поэтому в `manifest.json` он может быть отрицательным (например, `gate_barrier_mid` → (16, −9)). Положение в мире от этого не
  меняется. В таблицах ниже — **холст до обрезки** и его pivot.
- 1 клетка = 32 px арта = 1 юнит. Центр клетки: `CellCenter(c, r) = (c + 0.5, 0, Depth − r − 0.5)` (RUNTIME_SPEC §4.1).
- «Ноги (w/2, 0)» = нижний центр холста. Для построек это нижняя кромка footprint, для тайлов-«ног» — нижняя кромка клетки.
- Тайлы с `extrude` не обрезаются: холст 32×32, pivot (16, 16) или (16, 0), как указано.
- Варианты тем: для имён с пометкой «тема» есть `<имя>_crystal` и `<имя>_copper`. Брать через `PixelTheme.Name(name)`.

public const int Unload = 74, UnloadCount = 4;   // unload0..3 — сдача одной порции

- `carry*`: 0,10–0,11 с на кадр (у `walk*` 0,09 с).
- `pickup0→3`: на каждую порцию, равномерно по интервалу подбора.
- `unload0→2`: на каждую порцию, растянуть на время обслуживания порции. `unload3`: после `CargoDeposited` последней порции.
- Ожидание в очереди: `idle*`/`blink*` со слоем груза.

Лапки вырезаны из всех слоёв над телом.

**Слот → ключ вида.** Пустой слот → `base`. Предмет `pickaxe.common` → `cat_pick_common_*`, `hat.rare` → `cat_hat_rare_*`,
`backpack.epic` → `cat_pack_epic_*`, `boots.legendary` → `cat_boots_legendary_*`.
Префиксы слоёв (`pick`, `hat`, `pack`, `boots`) отличаются от ID слотов ТЗ (`pickaxe`, `hat`, `backpack`, `boots`), а иконки
используют ID слотов ТЗ (§6). Уровень предмета и локальные ветки внешний вид не меняют.

**Груз.** Слоя нет, пока сумка пуста. Иначе выбирается по заполнению `Bag.Count / Capacity`:
- `cat_load_1_*` — меньше 50 %;
- `cat_load_2_*` — меньше 100 %;
- `cat_load_3_*` — от 100 % (полная сумка или перегруз после смены рюкзака, ТЗ §10.3).

Это пороги RUNTIME_SPEC §4.2.

**Ходьба.** С пустой сумкой — `walk*` (кирка в лапках). При `Bag.Count > 0` — `carry*` (кирки нет).

**Таблицы для `OutpostLook`** (как `s_Body`/`s_Helmet` в `CatLook`): `string[5, 78]` для boots/pack/hat/pick и `string[3, 78]` для load.
Там, где кадра нет в наборе, — `null`. Спрайты брать заново только на `EquipmentChanged`.

**Старые слои.** `cat_helmet_{colour}_*` и `cat_weapon_{weapon}_*` есть только для прежних 62 кадров (`LEGACY_FRAMES`). Новый режим
их не использует, вместо них — `cat_hat_*` / `cat_pick_*`. Продлевать их на новые кадры не нужно.

### 3.2 Раскладка

Обозначения:
- столбцы 0–6;
- строки площадки `pad0..pad2` = `Depth..Depth+2`;
- строки двора `st0..st2` = `Depth+3..Depth+5`;
- нижняя стена — `Depth+6`.

Координаты в Unity — по формуле §1: `x` — от левой кромки столбца 0, `z` — мировая.

```
            col:   0        1        2           3          4        5        6
pad0  z=-0.5  edge_t   edge_t   edge_t      edge_t     edge_t   edge_t   edge_t
pad1  z=-1.5  floor    floor    SLOT(2)     спавн      SLOT(4)  floor    floor     ← depot_slot в (2,D+1) и (4,D+1); спавн (3,D+1)
pad2  z=-2.5  edge_b   edge_b   edge_b+chute edge_b    edge_b+chute edge_b edge_b  ← очередь котиков (без блокировки клеток)
st0   z=-3.5  ground   ground   ┌──────── depot_base ────────┐ ground   ground
st1   z=-4.5  WARDROBE HIRE     └──── ноги z=-5.0, x=3.5 ────┘ BENCH    RACK      ← задний ряд: ноги на нижней кромке st1 (z = −5.0)
st2   z=-5.5  LANTERN  SIGN     CRATE       ground     CRATE    CART     LANTERN   ← передний ряд: ноги на нижней кромке st2 (z = −6.0 + 1 px)
D+6   z=-6.5  wall_bottom ×7, углы wall_corner_bl/br, по бокам wall_edge_l/r на всех строках лагеря
```

| Объект | Ноги (x, z) | Порядок |
|---|---|---|
| `wardrobe_*` | (0.5, −5.0) | `OrderAt(−5.0)` |
| `hire_board_{t}` | (1.5, −5.0) | `OrderAt(−5.0)` |
| `depot_base` + `depot_glow` | (3.5, −5.0); занимает столбцы 2–4, строки st0–st1 | группа `OrderAt(−5.0)`, свет +1 |
| `bench_{t}` | (5.5, −5.0) | `OrderAt(−5.0)` |
| `rack_{t}` | (6.5, −5.0) | `OrderAt(−5.0)` |
| `camp_lantern_0` / `_1` | (0.5, −5.97) / (6.5, −5.97) | `OrderAt(−5.97)` |
| `camp_sign` | (1.5, −5.97) | ″ |
| `depot_crate_{f}` ×2 | (2.5, −5.97) и (4.5, −5.97), под воронками склада | ″ |
| `cart_{t}` | (5.5, −5.97) | ″ |
| `depot_slot*` | центр (2.5, −1.5) и (4.5, −1.5) | `FloorDecalOrder` |
| `depot_chute` | центр (2.5, −2.5) и (4.5, −2.5) | `FloorDecalOrder` |
| тайлы площадки и двора | центр клетки | `FloorOrder` (меш пола, как `BoardView`) |

Ни одна постройка не поднимается выше st0, поэтому очередь в pad2 ничем не закрыта.
Котики стоят ногами на `FeetY = −10 px` ниже центра клетки, как в `CatView`.

**Состояния (рекомендация, согласовано с RUNTIME_SPEC §4.3).**
- Ступень `t` постройки: 0 — уровень ветки < ⅓ cap, 1 — ≥ ⅓ cap, 2 — ≥ ⅔ cap. Ветки: доска найма — «Команда»; верстак — «Кирки»;
  стеллаж — «Сумки».
- Вагонетка: `cart_1`, когда ветка «Обувь» ≥ ⅓ cap.
- Ящики `depot_crate_0..3` — по доле доставленного груза шахты: 0, > 0, ≥ ⅓, ≥ ⅔.
- Шкаф: `wardrobe_open`, когда в коллекции есть ненадетые новые предметы.
- Место `n` занято (резерв или обслуживание) → `depot_slot_active`. Во время обслуживания → `depot_glow`.
