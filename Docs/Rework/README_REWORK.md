# Cat Miners — CatOutpostV2

Разветвлённые шахты включены во всех новых прохождениях. Начатая шахта из старого сохранения доигрывается на своей геометрии; следующая получает новую. Для просмотра сразу: отдельный Debug-профиль → выбор шахты. Подробности и снимки: [MINE_TOPOLOGY.md](MINE_TOPOLOGY.md).

Новый автоматический режим включён по умолчанию в `Assets/Game/Scenes/CoreGame.unity`.
Откройте сцену и нажмите Play: два бесплатных котика сами выбирают цели, добывают,
переносят груз и сдают его на базе. Деньги появляются только при сдаче.

«База» открывает шесть местных улучшений; «Экипировка» — постоянные предметы команды.
Тап или клик по доступному камню/завалу текущего сектора — удар золотой кирки игрока «из воздуха»:
небольшой урон (¼ удара котика), монеты выпадают на землю и приходят на склад с котиками.
Касание котика и удержание на любом объекте (0,45 с) показывают информацию. Перетаскивание
фона и колесо мыши прокручивают поле; «К базе» возвращает камеру. Окна и обучение оставляют добычу активной.
После расчистки котики доставляют остатки, затем открываются итоги и следующая шахта.
Местные уровни, деньги и нанятые котики сбрасываются; предметы, детали, карточки,
эликсир и настройки остаются.
После шахты 144 показывается завершение кампании.

## Карточки

Кнопка «Карты» открывает полную коллекцию 61 карточки источника: арт виден у всех, закрытые по прогрессу слегка затемнены
с подписью «Откроется на шахте N». Карточки — постоянные бонусы (сохраняются между шахтами) к цене, урону, скорости,
сумкам, найму, сундукам и т. д.; специалисты усиливают только свой ресурс. Копии и эликсир приходят из сундуков камней,
месторождений, ворот и выхода; первая карточка `ca001` — при первой доставке нового профиля. Улучшение тратит копии и
эликсир (`CardUpgradeCosts`), не золото и не детали. Подробно — [CARD_EFFECT_MAPPING.md](CARD_EFFECT_MAPPING.md),
ТЗ §10.4. Карточки и эликсир прежнего режима переносятся один раз; перед первой записью профиль копируется в `pre-cards/`.
В debug-профиле DEV → «Cards» выдаёт копии открытых карточек и эликсир для проверки улучшений.

## Запуск

Unity **6000.3.11f1**, портрет 9:16, Input System. После синхронизации:

```powershell
powershell -ExecutionPolicy Bypass -File Tools/unity.ps1 -Mode Setup -Target Auto
```

Setup проверяет исходный JSON, конфигурации и геометрию, обновляет ссылки сцены.
Профили игрока эта команда не загружает и не сбрасывает. Если основной проект открыт,
для команд проверки используйте `-Target Ci`: создаётся отдельная копия `build/ci`
со своей Library, пользовательский Editor остаётся открытым. Одновременно запускайте
только одну команду Unity, использующую эту копию.

Источник `Assets/Game/Data/Source/json-data.json` содержит все 144 карты и сохранён без изменений:
SHA-256 `8975a5a09dce8e2675d06b751c50b5cac80da3988f8ed098910492c442f85ee5`.
Числа нового режима находятся в пяти JSON `Assets/Game/Resources/Outpost/`,
включая `card_rules.json`.
Единственное исключение карт — override `zone1-full-arena-1` в `level_overrides.json`
(ТЗ 8.5): первая шахта заполнена целями почти целиком. Шахта, начатая до изменения
override, при загрузке начинается заново на новой карте; предметы и награды сохраняются.
Раскладку можно посмотреть так: `python3 Tools/LevelOverrides/show_zone.py 1 --overrides Assets/Game/Resources/Outpost/level_overrides.json`.
Независимый аудит с override: `python3 Docs/TZ/analysis/outpost_v2_audit.py Assets/Game/Data/Source/json-data.json --overrides Assets/Game/Resources/Outpost/level_overrides.json --out Docs/TZ/analysis/outpost_v2_audit.json`.
ТЗ реализации: `Docs/TZ/Cat_Miners_Auto_Incremental_TZ_v2.1.md`.
Параметры и замеры: [BALANCE_V2.md](BALANCE_V2.md).
Результаты и ограничения: [VALIDATION_V2.md](VALIDATION_V2.md).

## Профили и сохранение

`Application.persistentDataPath/CatOutpostV2/main/` и отдельно `.../debug/`
содержат `state.json`, временный файл и `.bak`. Один конверт хранит постоянный профиль,
текущую шахту, контрольную сумму и последовательность commit. Старые main/debug
архивируются копированием в `CatOutpostV2/legacy-archive`; оригиналы остаются на месте.
Совместимые настройки переносятся один раз. Старая экономика в новой сцене не запускается.

Автосохранение выполняется каждые 2 секунды. Покупки, экипировка, награды, офлайн
и переход записываются сразу согласованным снимком. При ошибке записи появляется
окно повтора; экономика останавливается, повтор записывает тот же подготовленный
результат. Покупка и бросок награды не выполняются второй раз. Повреждённый или
несовместимый профиль сохраняется для восстановления; пустая игра поверх него не создаётся.
При загрузке используется валидный main/backup с наибольшей последовательностью;
незавершённый временный файл не считается commit.

Онлайн использует монотонные часы и целые микросекунды. После паузы/потери фокуса
то же ядро считает отсутствие порциями на копии состояния: общий предел — 3 реальных часа,
включая старые сохранения. Затем котики отдыхают; остаток не доначисляется при повторном запуске.
«Лежанка» даёт +5% к скорости разгрузки за уровень. Результат
и UTC-маркер записываются до показа сводки. Офлайн заканчивается в текущей шахте,
автоматического перехода и покупок во время отсутствия нет.

## Код и инструменты

- `Scripts/Core/Outpost`: точная экономика, уровни, задачи, пути, порции, склад,
  экипировка, награды, переход, офлайн, сохранения и воспроизводимые боты.
- `Scripts/Runtime/Outpost`: контроллер, ввод, представление поля/котиков/груза,
  HUD, обучение, звук и связь со сценой.
- `Scripts/Editor/OutpostSetup.cs`, `OutpostValidatorCli.cs`: настройка и проверка карт.
- `Scripts/DevTools/OutpostDevPanel.cs`: панель DEV в Editor/Development Build.

В DEV сначала переключитесь на **Debug**. Выбор зоны, скорость ×1/×5/×20/×100,
тестовый комплект, завершение и просмотр путей защищены также внутри контроллера.
Обычный Main работает ×1. «Finish» обрабатывает реальную логистику ускоренно;
«New Debug» архивирует прежний Debug. Инструменты не меняют Main и не доказывают
обычное прохождение. Старые тестовые сцены используют явный `GameBootstrap.LegacyMode`;
обычная release-сцена выбирает Outpost.

```powershell
# Компиляция и все обычные проверки Unity
powershell -ExecutionPolicy Bypass -File Tools/unity.ps1 -Mode Compile -Target Ci
powershell -ExecutionPolicy Bypass -File Tools/unity.ps1 -Mode EditMode -Target Ci
powershell -ExecutionPolicy Bypass -File Tools/unity.ps1 -Mode PlayMode -Target Ci

# 144 изолированные карты, последовательная кампания, сравнение A/B/C
powershell -ExecutionPolicy Bypass -File Tools/unity.ps1 -Mode Validate -Target Ci

# Отдельные длительные проверки и артефакты
powershell -ExecutionPolicy Bypass -File Tools/unity.ps1 -Mode PlayMode -Target Ci -TestFilter OutpostEvidenceTests
powershell -ExecutionPolicy Bypass -File Tools/unity.ps1 -Mode PlayMode -Target Ci -TestFilter OutpostPerformanceTests
powershell -ExecutionPolicy Bypass -File Tools/unity.ps1 -Mode PlayMode -Target Ci -TestFilter OutpostGameplayRecordingTests
powershell -ExecutionPolicy Bypass -File Tools/unity.ps1 -Mode PlayMode -Target Ci -TestFilter OutpostCardsEvidenceTests
powershell -ExecutionPolicy Bypass -File Tools/unity.ps1 -Mode BuildApk -Target Ci
```

Логи, XML/JSON и снимки: `Docs/Reports/outpost/`, общие логи Unity: `Docs/Reports/`.
Полные EditMode/PlayMode сохраняются также в `*-all-results.xml` и `unity-*-all.log`.
Запуски с `TestFilter` сохраняют отдельные XML/логи по имени фильтра; генератор
карточек не перезаписывает доказательство полного набора.
Склейки коллекции и GIF собираются из кадров Unity скриптом
`python3 Tools/Cards/make_card_evidence.py` на хабе; история кадров указывает
ускорение ×20 и debug-выдачу для демонстрации улучшения.
Валидация проверяет инварианты после каждой обработанной отметки и round-trip
состояния кампании; timeout/watchdog считается провалом. Видео использует обычный
Main, SystemClock и сценарные покупки за доставленные деньги; два фрагмента одной
живой игры соединяются с пропуском ожидания. Ускорения и выдачи ресурсов в записи нет.

`Tools/UnityCheck/run.ps1 -Project All` компилирует против DLL установленного Editor,
но не исполняет сцену. Чистые тесты ядра также доступны через
`Tools/CoreTests/run.ps1 -Filter 'FullyQualifiedName~Outpost'`.
Для сборки Android нужны Android Build Support, SDK, NDK и OpenJDK.
