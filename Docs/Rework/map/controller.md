# Reuse map: controller subsystem

> **Устарело для карточек (9 октября 2026).** Решение отключить карточки, manager-карты, сундуки и эликсир отменено: система 61 карточки возвращена в режим CatOutpostV2 (ТЗ §10.4, `Docs/Rework/CARD_EFFECT_MAPPING.md`). Пометки DROP/удалить ниже для карточек, `Gacha`, `RewardCycle` (карточки и эликсир), `cards.py`, `HudBlueprints` и `UpgradeCard` больше не действуют; это карта прежнего кода, а не инструкция.

Scope: `Assets/Game/Scripts/Runtime/` → `GameController.cs` (1224 lines), `GameBootstrap.cs` (35), `CameraRig.cs` (389),
`PointerInput.cs` (402), `SystemClock.cs` (18), `Haptics.cs` (78), `VisualSettings.cs` (14), `PresentationCatalog.cs` (433).
Target: the new auto-incremental mode (`Docs/TZ/Cat_Miners_Auto_Incremental_TZ_v2.1.md`, below "TZ2").
All line refs are `file:line` relative to `Assets/Game/Scripts/Runtime/` unless a path is given.

Verdict legend: **REUSE** (as is) · **ADAPT** (keep the shape, change what's listed) · **DROP** (not needed in the new mode).

## 0. TL;DR

- **GameController is a god object.** It owns the frame loop, saves, offline handling, event presentation, the UI command
  surface, the camera policy and zone transitions. About 60% of it is old-gameplay command code (merge, drag, dynamite,
  generators, cards, chests, shafts). The **skeleton is worth keeping**: Init order, Clock injection, the Update time
  policy, `DrainEvents` (save → bus → present, each guarded), the `SaveNow` + pause/focus/quit lifecycle, and the
  `ZoneTransition` coroutine pattern. Write a new `OutpostController` (or gut this one) around a new `OutpostSession`.
- **CameraRig is almost pure.** Its only gameplay coupling is `HomeFocusZ(GameSession)` (`CameraRig.cs:242`).
  Reuse it, and replace HomeFocusZ with a "base row" focus for the TZ2 "К базе" button.
- **PointerInput can be kept with cuts.** Keep the action-map plumbing, the UI-ownership test, tap vs. scroll, fling and wheel.
  Remove the cat drag, dynamite drag and the Loot-tap path. TZ2 §5 says coins on the ground are cargo and tapping them must not collect them.
- **SystemClock, VisualSettings and GameBootstrap: REUSE.** Haptics: small ADAPT (it takes `GameSession` only to read `VibrationOn`).
- **PresentationCatalog: split it.** The rock/obstruction/shaft/theme/music visuals are reusable, because TZ2 §8.2 keeps the source IDs and
  `MimicId` for visuals. The whole Card* block and the Gacha names are DROP.
- **Gaps against TZ2 that this layer has today:** no Android Back handling, no gesture cancel when a modal opens (TZ2 §14),
  no per-frame "follow" camera API, and save paths are `save_<slot>.json` rather than `CatOutpostV2/main|debug/` (TZ2 §17).

## 1. How the scene is built at runtime

Scene `Assets/Game/Scenes/CoreGame.unity` is generated by `Scripts/Editor/ProjectSetup.cs:172 CreateScene`. It contains:
Main Camera (with **AudioListener**, ortho, pitch 90), Directional Light, EventSystem + `InputSystemUIInputModule`,
an "HUD" Canvas with a "SafeArea" child (`ProjectSetup.cs:277`), and a "Bootstrap" GO with `GameBootstrap`
(BalanceJson, Lit/Unlit/Particle/Sprite materials, InputActions).

Runtime chain:
1. `GameBootstrap.Awake` (`GameBootstrap.cs:25`) sets `targetFrameRate = 60`, `vSyncCount = 0` and
   `ActiveInputActions = InputActions`. It creates GO "CatMiners", adds `GameController`, then calls `Controller.Init(this)`.
2. `GameController.Init` (`GameController.cs:111`) runs in this **order (matters)**:
   - `Clock = ClockOverride ?? new SystemClock()` (113). In Editor/DevBuild it registers `ZoneCompletionLog` on `Bus` (115).
   - `Materials.Init(lit, unlit)`, `PixelArt.Init(sprite, unlit)` (116-117). These are global statics used by every view.
   - `EnsureSceneBasics()` (158): adds a Light if missing, sets the flat ambient, and ensures EventSystem + InputSystemUIInputModule
     (`AssignDefaultActions` if the module has no asset).
   - Takes `Camera.main` or creates "Main Camera" (119-124). **That fallback camera gets no AudioListener**, so there is no sound.
   - `Rig = CameraRig.Create(cam)` (125). `Fx = Effects.Create(transform, particleMat)` (126).
   - Audio: `Sfx.Create`, `MusicPlayer.Create`, `Ambience.Create`, all parented to the controller (128-130).
   - `Board = new GameObject("Board").AddComponent<BoardView>()`, parented to the controller, subscribed to `ContainerLanded` (131-133).
   - `Hud = Hud.Create(this)` (134). It reuses the scene Canvas (`UI/Hud.cs:197`) and sets sortingOrder 30000.
     Then `Hud.OnChestsBadgeTap = ShowPendingChests`.
   - `Input = gameObject.AddComponent<PointerInput>(); Input.Init(this)` (136-137).
   - `Tutorial = new TutorialController(this)` (138). The HUD wires `Tutorial.Hint` in its `Start` (`UI/Hud.cs:766`), so the
     Tutorial **must** be created in the same Init after the HUD.
   - Balance load (140-151): on failure it sets `m_FatalError`, shows `Hud.Modal` and returns, so the Update loop stays disabled.
   - `SaveDirectory = SaveDirectoryOverride ?? Application.persistentDataPath` and `m_Saves = new SaveService(dir)` (153-154),
     then `LoadSlot(SaveSlots.Main)` (155).
3. `[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]` installers in the DevTools asmdef read `GameBootstrap.Controller`
   (see §8).

New-mode note: keep the Bootstrap → Controller.Init pattern and the Init order (materials → camera → fx/audio → board →
HUD → input → tutorial → config load → save load). Replace `BalanceRepository.Load` with the source importer plus Outpost configs
loaded from Resources/StreamingAssets (TZ2 §18: they must work in the Android player). Add an AudioListener in the fallback camera path.

## 2. Per-frame loop (`GameController.Update`, 441-480)

```
mono = Clock.MonotonicSeconds; realDt = max(0, mono - m_LastMono)
now  = Clock.UtcNowMs;         gapMs  = now - Session.State.LastProcessedUtcMs
if (realDt > MaxFrameSeconds(1.0) || gapMs > 1000):      // pause, minimise, breakpoint, slow first frame
    Input.CancelAll(); OfflineProgress.Apply(Session, now); drop the offline events; SaveNow(); Hud.ShowOffline(summary)
else:
    speed = Session.IsDebugSlot ? SimSpeed : 1.0
    Session.Advance(SecondsToTicks(min(realDt, 1.0) * speed)); OfflineProgress.MarkProcessed(Session, now)
if (!InTransition): DrainEvents(); Board.SelectedCatId = ...; Board.Sync(Time.deltaTime); UpdateContextCamera(); Tutorial.Update()
m_SaveTimer += realDt; if (m_Dirty && m_SaveTimer >= SaveIntervalSeconds(2.0)) SaveNow()
```
- Sim time comes from `IClock.MonotonicSeconds` (realtimeSinceStartup), **not** from `Time.deltaTime`. View interpolation
  (`Board.Sync`) uses Unity `Time.deltaTime`. Camera, transition and kick use `Time.unscaledDeltaTime`.
- `ClockOverride` (34) is a static seam. Tests set `new ManualClock(utcMs, 100.0)` (Core/Sim/Clock.cs:21) **before** loading
  the scene, which makes the clock frozen and prevents frames longer than 1 s in batchmode from being treated as offline.
- `SimSpeed` (73) is applied only when `Session.IsDebugSlot`, and `SetSession` resets it to 1 for Main (343). TZ2 §19 wants ×1/×5/×20/×100.
  DevPanel already offers exactly these values (`DevTools/DevPanel.cs:86-90`).
- The ticks are already in microseconds: `GameSession.TicksPerSecond = 1_000_000` (Core/Sim/GameSession.cs:15). This matches TZ2 §6.5.
- Model and view are fully decoupled: during `InTransition` the sim keeps advancing, and only the draining and view sync pause.

ADAPT: keep this policy as is. Swap `OfflineProgress.Apply/MarkProcessed` for the new `OfflineSimulator` (TZ2 §13: same sim, 8 h cap,
stops at `ReadyToContinue`). TZ2 §6.5 has a seven-phase tick order. Make sure `Advance(dt)` processes whole ticks/events and that
`SaveNow` is only ever called between `Advance` calls; it is today, because `SaveNow` runs from Update/Drain after Advance returns.

## 3. SimEvent dispatch (`DrainEvents` 513-573, `Present` 576-710)

1. Re-entrancy guard `m_Draining`. It copies `Session.Events` into the reusable `m_Batch` (element by element: "List.AddRange in
   Mono allocates", 521) and clears the source list.
2. `m_Dirty = true` whenever any event exists. If any event is a commit event (`IsCommitEvent`, 486), it calls `SaveNow()`
   **before** presentation. This is the TZ2 §17 "immediate commit after purchase/reward/transition" hook.
3. `Bus.Dispatch(Session, m_Batch)` in a try/catch. `SimEventBus` (Core/Sim/SimEvent.cs:76) only routes `MineCompleted` to
   `IZoneCompletionHandler` and dedups by `OpId` (512 remembered).
4. For each event, `Present(e)` in its own try/catch, so one throwing view does not block the rest and the batch is not replayed.
   `m_PresentIndex` lets `LootCellOf` find the paired event in the same batch.
5. Post-batch actions: open a pending chest if no modal is shown, and show campaign end.

`Present` fans each event out to: `Board.OnEvent(e, Fx)` → `Tutorial.OnEvent(e)` → a switch on `SimEventType` that drives Sfx, Haptics,
`Rig.Kick`, `Hud.Toast`, `FloatingText.Spawn` and `Hud.FlyLoot`. Events handled: TargetHit, RockDestroyed, RewardGranted,
LootDropped, LootCollected, ContainerSpawned, PayoutCollected, CatSpawned, CatMerged, CheckpointOpened,
MineShaftActivated, ShaftAutomated, GeneratorUpgraded, CardUpgraded, ThresholdReached, ChestOpened, ContainerOpened,
DynamiteUsed, GateBroken, ExitBroken, CampaignCompleted, ShaftCleared, CommandRejected, ZoneEntered (it rebuilds the board).
`TakeBudget` (732) caps "+N" floats and HUD fly-ins at 6 per frame (`LootPresentPerFrame`, 43), which throttles mass presentation.

ADAPT: keep the drain skeleton (copy → commit save → bus → guarded present → post actions) and `TakeBudget`. Rewrite
`IsCommitEvent` and `Present` for the TZ2 events (`CargoReleased`, `CargoPickedUp`, `CargoDeposited`, `TeamUpgradePurchased`,
`EquipmentChanged`, `SectorOpened`, `StageCompleted` …). TZ2 §16: the coin fly-to-wallet happens **only on deposit at the base**,
never on hit or drop. TZ2 §16: with 12 cats, deposit sounds must not become a constant noise, so reuse `TakeBudget` for SFX too.
`SimEventBus` is MineCompleted-only. Generalise it or keep it for `StageCompleted`.

## 4. Saving and lifecycle

| Trigger | Where | Notes |
|---|---|---|
| Dirty plus a 2 s timer | `Update` 478-479 | `m_SaveTimer` accumulates realDt and is reset by every SaveNow |
| Commit event in a batch | `DrainEvents` 527-528 | before Bus/Present |
| Offline catch-up | `Update` 459, `LoadSlot` 257 | |
| Pause (`OnApplicationPause(true)`) | 785-793 | `AudioListener.pause = paused` (also on resume), CancelAll, CancelCatDrag, SaveNow |
| Focus lost | 795-800 | CancelAll and SaveNow |
| Quit | 802 | SaveNow, which is not reliable on Android (TZ2 §17 "не полагайся только на закрытие") |
| Zone transition | `ConfirmCompleteZone` 1146, `ZoneTransition` 1182 | one save right after the transaction, one after the new map |
| Chest claim | `ShowPendingChests` callback 759 | |
| Slot switch | `SwitchSlot` 426, 432 | |

`SaveNow` (765-783) returns when `m_SaveBlocked`, which happens after a corrupt or incompatible load until the player confirms
"Начать заново" (`OfferRestart` 312). It stamps `OfflineProgress.MarkProcessed(now)` and writes the camera `Mine.CameraFocusZ = Rig.FocusZ`
**only if** `ReferenceEquals(m_BoardMine, Session.Mine)` (774), so it never writes a stale camera into a new zone. Then it calls `m_Saves.Save(state, now)`.
Exceptions are logged and swallowed.
`LoadSlot` (185-267) handles `LoadStatus` Loaded/LoadedFromBackup/RulesChangedMineReset/IncompatibleBalance/Corrupted.
It quarantines files (`*.corrupt-*`, `*.leftover-*`, `*.incompatible-*`) and never overwrites them. It then runs offline, clears the events, saves,
and shows modals.

ADAPT: keep the trigger table, `m_SaveBlocked` + OfferRestart and the camera-stamp guard. TZ2 §17 requires the new SaveService
envelope (`modeId=CatOutpostV2`, schema/rules/balance versions, `commitSequence`, dirs `persistentDataPath/CatOutpostV2/main|debug/`).
TZ2 forbids a hidden reset on rules change, so **DROP `RestoreWithMineReset` (274)**. Also TZ2 §17: if a save fails, retry the write.
Do not repeat the transaction. Today the failure is only logged.

## 5. Input routing

`PointerInput.Update` (196-322) polls actions every frame (no callbacks). States are `Mode { None, Pending, DragCat, Scroll, OverUi, DragDynamite }` (25).
- `m_Game.InTransition` → CancelAll and ignore (200-204). A system-cancelled touch (`PrimaryTouchPhase == Canceled`) → CancelAll (213-217).
- Mouse wheel when idle and not over UI → `Rig.ScrollWorld(±1.2)` (219-223).
- Press down: `Rig.StopFling()`. Over UI (EventSystem.RaycastAll) → `OverUi`, which swallows the gesture. Otherwise `Pending` plus `PickCat(pos)` (243-258).
- Pending + release → `Tap(pos)`. Pending + moved ≥ `DragThresholdPixels` → `DragCat` if the press was on a cat, else `Scroll` (266-283).
- Scroll: `Rig.ScrollByPixels(dy)` each frame with a smoothed velocity; release → `Rig.Fling(v)` (285-296).
- DragCat → `UpdateCatDrag`, `AutoScroll`, drop → `DropCat(id, gx, gy)` via `Rig.ScreenToGround` + `Board.WorldToGrid` (297-319).
- DragDynamite: started by HUD → `BeginDynamiteDrag()` (185). Release → `UseDynamite(gx, gy)` (225-241).
- `Tap` (366-400): `Physics.RaycastAll` on 3D colliders carrying `Pickable` (`Visual/Views.cs:11`, `{Kind: Cat|Object|Container|Loot; Id; Bubble}`).
  Priority: Loot(-2) < Bubble(-1) < Container(0) < Cat(1) < Object(2), then distance. Dispatch: Loot→`CollectLoot`, Container→`OpenContainer`,
  Cat→`SelectCat`, Object→`TapObject`, nothing→`ClearSelection`.

New mode (TZ2 §5): there is no drag of cats, no dynamite and no loot tap. Background drag is camera only. Tapping a cat or a target shows info.
So keep `None/Pending/Scroll/OverUi`, and `Tap` with the priorities `Bubble < Cat < Object` (plus a new `Base`/building kind for the depot).
DROP DragCat/DragDynamite/AutoScroll, or keep AutoScroll for no purpose.

## 6. Zone transitions

`TapObject(exit)` / HUD button → `RequestNextMine` (1089): `CanCompleteZone(out reason)` fails → Toast + `FocusInactiveShaft`.
On success → a confirm modal with "stay"/"go" → `ConfirmCompleteZone` (1136). That method calls `Board.PrepareExitWalk()` **before** the transaction (the paths
need the old state), then `Session.CompleteZone()`, `SaveNow()`, `ClearSelection()`, `StartCoroutine(ZoneTransition())`.
`ZoneTransition` (1159-1190): `InTransition = true` (input blocked, drain paused), CancelAll, `Hud.BeginTransition()`,
`Rig.FocusOnSmooth(exit.z, 0.6)`, Fx glow/puff/sparkle, Sound.GateOpen, `Board.PlayExitWalk()` (wait for its duration), fade-out 0.3 s,
then `InTransition = false` → `DrainEvents()`. The pending `ZoneEntered` → `Present` → `RebuildBoard(false)` (701-708). Then `SaveNow`,
`Hud.Refresh`, fade-in 0.35 s, `Hud.EndTransition()`. All timing uses `Time.unscaledDeltaTime`.
`CompleteZoneNow` (1120) is the same path without the modal (LevelCheat).
`RebuildBoard(bool restoreCamera)` (404-421): `Board.Build(Session)`, sets the camera bg to `PixelTheme.Dark`, applies zone music, stamps `m_BoardMine`,
calls `Rig.SetUiInsets(Hud.TopInset, Hud.BottomInset)` and `Rig.SetBoard(width, depth, savedZ or cart-row z)`, then `Rig.FocusOn(HomeFocusZ)`.

ADAPT: the pattern of transaction + save first and the animation afterwards, with the new-zone events held back until the fade, matches
TZ2 §11.3 and §17 ("Командные результаты/окна награды/перехода подтверждаются UI после успешной записи"). Gate the "go" button on
`ReadyToContinue`, and show the "Итоги шахты" window (item, details, reset explanation) in place of the old modal.
Exit walk → "сбор команды после завершения" (TZ2 §16).

## 7. Camera policy inside the controller

- `UpdateContextCamera` (874-904): it lifts the selected cat or object above the context panel (`Hud.TryGetContextTop` → `Rig.SetContextTop` /
  `Rig.RevealAbove`), and skips while dragging. **ADAPT**: keep it for the TZ2 cat/target info panels. Remove the drag checks.
- `FocusIdleCat` (1035) cycles through idle cats with `Rig.FocusOn(Depth - row - 0.5)`. **DROP**, because idle cats do not exist in TZ2.
- `FocusInactiveShaft` (1056) cycles the camera through not-yet-activated shafts within 4 s (`ShaftCycleSeconds`). **DROP**, but the
  cycle-on-repeat-tap pattern can be reused for "next blocking target" hints.
- Row → world z: `z = Depth - row - 0.5` (cell centre, `Visual/BoardView.cs:139`). Grid ↔ world: `GridToWorld(gx, gy) = (gx, 0, Depth - gy)`
  and `WorldToGrid(w) = (w.x, Depth - w.z)` (`BoardView.cs:140-141`). **TZ2 §8.3 puts the base on 3 extra rows `Depth..Depth+2` below the map.**
  Pass `depth + 3` to `Rig.SetBoard`, and use the same total depth in the board z mapping. Otherwise the base lands at negative z, below `MinZ`.

## 10. Gotchas noticed in comments and code

1. **Batchmode frames longer than 1 s** (first shader compile) count as offline and pop "Пока вас не было". PlayMode tests must set a frozen
   `ClockOverride = new ManualClock(utc, 100.0)` before `LoadSceneAsync` (`Tests/PlayMode/PointerInputTests.cs:52-54`).
2. **Batchmode has no window focus**, so the UI module ignores input. Tests set `InputSystem.settings.backgroundBehavior = IgnoreFocus`
   (`PointerInputTests.cs:73`). `OnApplicationFocus(false)` fires CancelAll and SaveNow in Editor too.
3. **InputTestFixture vs. a leftover scene.** The previous scene's PointerInput must be disabled before the input system is swapped, or there is an NRE in
   InputActionState (`PointerInputTests.cs:25-44`). That is why PointerInput uses a private `Instantiate` copy and `Dispose` on OnDisable
   (`PointerInput.cs:60-63, 120-131`). The UI module also needs a fresh `actionsAsset` copy in tests (`PointerInputTests.cs:76-80`).
4. **Input is polled, not callback-based.** InputAction callbacks report the previous frame's UI state, so UI ownership is resolved with
   `EventSystem.RaycastAll` at the moment of the press (`PointerInput.cs:14-15`).
5. A **Pending tap does not re-check UI on release** (`PointerInput.cs:268-272`). If a modal opens mid-press, the release taps the board under it.
   TZ2 §14 needs `Input.CancelAll()` on modal open. Nothing calls it today (only pause, focus, transition and session swap do).
6. **No Android Back handling** anywhere in Runtime. TZ2 §14 requires "Back closes the top window, then the selection".
7. **Allocations:** `IsOverUi` allocates a new `PointerEventData` per call. It runs on every press and on every wheel frame. `Physics.RaycastAll` allocates
   arrays on every tap. Fine for taps, but do not call these per frame. The `DrainEvents` copy is deliberately element by element to avoid a Mono `AddRange` temp array.
   `UpdateContextCamera`/`SetContextTop` say they are allocation-free. TZ2 §19 budget: 1 KB GC per frame.
8. `SaveNow` stamps `LastProcessedUtcMs`, so saving more often never "loses" offline time. The camera Z is written only for the mine the board was built for.
9. The new zone's events are **held** during `InTransition` while the sim keeps running, then drained at once. With TZ2 automation, the first frame after the fade
   can carry a large batch, and `TakeBudget` exists for that.
10. `OnApplicationQuit` is not reliable on Android. Pause/focus are the real save points (TZ2 §17).
11. The fallback camera created in `Init` has **no AudioListener**. ProjectSetup's camera has one (`Editor/ProjectSetup.cs:194`).
12. `CameraRig.SetUiInsets` arrives late: the HUD measures its bars after layout and pushes the values again via `Hud.PushInsets`. The rig refits and keeps
    `FocusZ`. Do not cache `BandWorldHeight()` across frames.
13. The camera position is pixel-snapped (`PixelWorld.Snap`, 1/32 cell). Any new follow/lerp must go through `Apply()` or sprites will jitter.
14. `CameraRig.OverrideAspect` is a static that tests set (`CoreGameSmokeTests.cs:32`). Reset it in TearDown.
15. `Haptics`: keep the dead `Handheld.Vibrate()` call for the manifest permission.
16. `SimSpeed` is silently forced to 1 outside the Debug slot (343, 464). DevPanel shows a toast (`DevPanel.cs:192-197`).
17. Old core rule toggles `BarrelHires/LootPickups/AutoMining` are set per session in `SetSession` (338-340). TZ2 §4 says old timers and auto-collect (30 s)
    must be **really** disabled, not hidden. The new controller must never construct the old `GameSession` in the normal mode.
