# Проверка возможностей панели перед созданием записей

Выполни один набор read-only проверок в текущей пользовательской сессии. Успешный вход и видимая кнопка не подтверждают рабочий upstream credential, право записи или готовность всех сервисов. Сохрани результат отдельно по каждой нужной операции, затем выполняй независимые этапы.

## Подтверждённые чтения на 2026-10-08

Это пути API-клиента UI, а не гарантированный публичный HTTP-контракт. Их наличие подтверждено исходником текущего frontend и фактическими read-запросами; base path/auth определяй по текущему клиенту, без придуманного `/api` или заголовков.

| Запрос | Форма / результат пробного запуска |
| --- | --- |
| `GET /projects` | `success`, `data[]`: `id`, `name`, `androidPackageName`; настройки связей имеют поля вроде `facebookAppId`, `appMetricaAppId`, `adjustTrackerToken` |
| `GET /monetization/ad-units` | `success`, `data[]`: `id`, `name`, `platform`, `ad_format`, `package_name`, `disabled` |
| `GET /google-play-apps` | `success`, `data[]`: `packageName`, `displayName`, `iconUrl`; это lookup, не доказательство прав загрузки AAB |
| `GET /monetize/provider-connections` | `Unauthorized` в пробном запуске |
| `GET /adjust-apps` | upstream Adjust `401 Unauthorized` в пробном запуске |
| `GET /adjust-automation/apps/list` | `401` в пробном запуске |
| `GET /facebook-apps/provision/health` | `success`, `data.configured=false`: UI создания Meta есть, служба не подключена |
| `GET /facebook-apps` | `success`, `data[]` пустой; проверь также health, пустой список не подтверждает право создания |
| `GET /appmetrica-apps` | upstream AppMetrica `403 invalid_token / Invalid oauth_token` |
| `GET /admin/adjust-automation-settings` | `Unauthorized`; настройки глобальной интеграции этим аккаунтом не прочитаны |

MAX format codes в UI: `REWARD`, `INTER`, `BANNER`. Сопоставляй блоки по **package_name + Android platform + format**, не по похожему названию. Общий список может включать много приложений и не совпадать с отфильтрованными строками экрана. Поле `adjustTrackerToken` не является доказательством наличия Adjust **SDK app token**. Сохраняй назначение каждого токена, не подставляй один тип вместо другого.

## Как читать без повторного поиска в кабинетах

1. Предпочти подключённый MCP панели и его реальные read tools. Для проверки browser-only сессии доступны semantic UI actions.
2. Если UI скрывает диагностический результат, можно вызвать **read-метод используемого UI API-клиента** через browser evaluation, предварительно изучив загруженный модуль. В проверенном frontend `AdsMonetizationView` импортировал API-клиент из основного `index` модуля. Имена exports и asset hashes меняются: обнаруживай их в текущем module, не хардкодь старое имя.
3. Выводи только safe shape/count/public identity и error status. Не выводи объект клиента, cookies/localStorage, auth headers, provider credentials или полные ответы настроек.
4. Записи через MCP/UI/API выполняются по реальному контракту после подготовки данных конкретной игры. Перед первым write сверяй его action/payload/target по фактической форме/документации, затем перечитай запись. В этом пробном запуске write-маршруты не проверялись.

## Ошибки доступа

После проверки собери и запроси конкретные недостающие доступы по [service-access.md](service-access.md). При отсутствии рабочего маршрута панели допускается подключение к самому сервису с предоставленным доступом; приложения создаёт агент. Старые401/403/configured=false в этой справке — исторические результаты, не причина повторно запрашивать уже работающие доступы или считать текущую службу отключённой.

При upstream Adjust 401 не проси повторить вход Google в уже работающую панель без признаков истечения её сессии. Отметь конкретную интеграцию/операцию как недоступную, попроси владельца восстановить её доступ и продолжи код/зависимости/сборку. `Unauthorized` provider-connections может обозначать отдельное право, а не отказ всех остальных методов: не останавливай рабочие чтения и не пытайся многократно обойти отказ.

Если нужных AppMetrica/Meta действий в доступных инструментах нет, честно отдели известные поля привязки от способности создать приложение. Не утверждай, что панель умеет полную регистрацию только из-за присутствия `appMetricaAppId`/`facebookAppId` в проекте. Получи конкретный недостающий маршрут/доступ, подготовив остальные этапы.

## Найденная форма создания Meta

Если в каталоге MCP есть `facebook_create_app`, создавай приложение по [superleo-facebook.md](superleo-facebook.md). Форма ниже — запасной путь, когда этих операций нет.

Форма находится в frontend-модуле `AdminPanelView` у настроек проекта; проверяй этот модуль, даже если главная страница рекламной монетизации не показывает кнопку. В текущем UI она называется «Создать приложение в Meta». Наличие формы подтверждено её кодом, успешное создание пока не проверено: health вернул `configured=false`, переход аккаунта в `/admin` перенаправил на `/generator`.

Контракт формы: `POST /facebook-apps/provision` с `{projectId, name, platform: "android", androidPackageName}`, опционально `adAccountId`. При `configured=false` форма отключена и сообщает о ненастроенных `FB_PROVISION_URL / FB_PROVISION_TOKEN`; не запускай создание и не подставляй выдуманные подключения. При работающей службе сначала сверяй `/facebook-apps` и привязку проекта по store URL/package, затем используй этот маршрут вместо ручного обхода Meta Dashboard. `force` означает создание дубля и по умолчанию не передаётся.

Ответ `APP_EXISTS` с `existingAppId` — повод переиспользовать и перечитать приложение. Успешный ответ содержит `appId`; отдельно проверяй `verificationWarning`, наличие `clientToken` и сохранение Android-платформы. Ошибка может содержать `data.partial` и уже созданный `data.appId`: сначала перечитай это приложение, не повторяй POST. UI допускает ожидание до 12 минут; запускай с неблокирующим состоянием и сообщай прогресс, не объявляя создание законченным до read-back.

Получение SDK client token через эту службу: `POST /facebook-apps/client-token` с `{projectId, appId}`. Сохраняй токен локально или в секретах проекта, не выводи полный ответ. Связь проекта обновляется только полями этой игры; не отправляй устаревшую копию всей карточки.

## Проверенные записи — Piggy Payday, 2026-10-08

После отдельного поручения владельца в реальном аккаунте проверены следующие операции UI API-клиента. Перед записью найдены существующие сущности по Android package; после каждой операции выполнен read-back. Это подтверждение данных операций, не всех upstream сервисов и не Android SDK runtime.

- `POST /projects`: `{name, platform: "android", androidPackageName}` создаёт карточку проекта **без** Adjust token. Это позволяет независимо подготовить MAX, когда мастер Add App требует Adjust, а upstream Adjust возвращает 401. Не подставляй фиктивный токен. Карточка проекта панели не означает регистрации AppMetrica/Adjust/Meta.
- `POST /monetization/ad-units`: `{name, platform: "android", package_name, ad_format}` создаёт MAX блок. Форматы `REWARD`, `INTER`, `BANNER` проверены по одному; все три вернулись в `GET /monetization/ad-units` с правильными package/platform/format и `disabled=false`.
- Чтение с `{params: {package_names: packageName, platform: "android"}}` поддерживается клиентом; дополнительно сверяй поля каждой строки. Пустой `ad_network_settings` означает отсутствие подтверждённых настроек сторонних сетей. Не отмечай AdMob/Unity/Mintegral/Pangle настроенными только по созданию MAX блока.

Используй фактический текущий клиент и проверенный payload; HTTP auth/base path не выдумывай. Если POST завершился ошибкой/таймаутом, сначала перечитай состояние; существующий проект/блок переиспользуй. Привязки новых AppMetrica/Adjust/Meta ID добавляются только после регистрации/проверки соответствующего сервиса.

Сессии браузеров различаются: авторизация обычного Chrome пользователя или панели не гарантирует авторизацию кабинета в preview/Playwright. Проверь фактический URL/экран нужного сервиса. Если это login, выбери подключение к уже авторизованному Chrome либо вход в управляемом браузере. Продолжай доступные операции независимо от ожидания доступа.

Google Play `/u/0`, `/u/1` — изменяемые индексы Google-сессии, не идентификаторы организации. После переноса/повторного входа сверяй фактический Google account и developer ID, app ID/package; новый индекс может открыть другую организацию. Не записывай в неё данные выбранной игры. Scoped cookies могут импортироваться, но кабинет всё равно считать аккаунты signed out. Тогда продолжай через явно разрешённый подключённый Chrome либо запроси штатный вход в отдельном браузере; не считай файл cookies подтверждением авторизации.

## Браузер с авторизацией: агентский Chrome

Браузерные действия в панели и кабинетах — через agentb ([browser.md](browser.md)): вход передаётся на хаб после штатного согласия Chrome (`login-hub superleo`, Play/Adjust/AppMetrica по необходимости), MCP-браузеры не нужны.

Если пользователь **явно поручил перенос сессий**, допускается сохранить session state только нужных кабинетов через подключённый browser API в локальный игнорируемый файл с ограниченным доступом. Не выгружай весь профиль, историю или пароли: для продолжения в отдельном браузере нужны сессии конкретных сервисов. Не выводи cookies, auth headers и токены в чат/логи. `access.local.json` содержит ссылки на файлы и назначение credentials; credential-файлы не упаковываются в скилл. После импорта проверь реальный кабинет, аккаунт и право нужной операции: наличие файла ещё не доказывает рабочую авторизацию. При challenge/истёкшей сессии используй штатный вход владельца. Предпочти официальный API token/OAuth, если сервис позволяет нужную автоматизацию без browser state.

## Проверка отдельной сессии и узкий fallback

При явно разрешённом переносе учитывай не только cookies: панель хранит рабочий контекст пользователя в sessionStorage. В проверенном UI штатный Email → Access Studio восстановил вход; её API-клиент использует `/api` и заголовки `x-user-email`, `x-user-role`, `x-user-partner-id` из фактической сессии. Не придумывай роль/административный доступ. Сохраняй необходимое состояние нужного origin приватно. Для оригинальных SDK-кабинетов перенесённые cookies проверяй отдельно: успешный вход в Adjust/AppMetrica не доказывает работоспособность Meta через панель. Прямые страницы MAX и Meta и перенос их сессий не используются.

В локализованном Chrome remote-debugging запрос может называться «Разрешить удаленную отладку?» с кнопкой «Разрешить». При разрешённом подключении проверяй точный диалог/процесс; не принимай другие запросы. Агентский браузер запускай с отдельным private user-data-dir и проверяй, что процесс пережил завершение удалённой команды. Не меняй профиль и жизненный цикл личного Chrome.

Если upstream AppMetrica/Adjust панели не работает, но уже есть разрешённый рабочий вход в сервис, выполни только необходимую операцию напрямую. Для MAX и Meta прямой маршрут не применяется: нужен рабочий сервис панели. Проверенный маршрут Adjust: AppView → существующая игра → Platforms → Android → Google Play Store → App ID = точный Android package → Apply → **Save**. Apply закрывает форму, Save сохраняет платформу; перечитай результат после сохранения. Затем SDK integration → App token, сохрани токен приватно. Сначала ищи существующее приложение, не создавай дубль по одному отсутствующему полю. Отсутствие страницы Play не заменяй чужим package. Получение собственного SDK token не подтверждает работу SDK на устройстве.

## Браузерные маршруты панели без MCP (проверено 2026-10-13, `/mcp` = 503)
Из вкладки панели: `fetch` с заголовком `x-user-email` = `sessionStorage.userEmail` (cookie-сессии нет; без заголовка 401).
- `GET /api/projects` (поля `id,name,androidPackageName`), `GET /api/admob/apps` (60), `POST /api/admob/provision` (воркер падает на `Add an app`, 502).
- AppMetrica: чтение `GET /api/appmetrica/applications` (поля `id,name,category,time_zone_name,hide_address,gdpr_agreement_accepted,permission,sdkKeyAvailable`) и `GET /api/appmetrica/categories`; создание `POST /api/appmetrica/applications`. `/api/appmetrica-apps` в этом клиенте только читает, POST там 404.
- Создание требует явных `name, category, time_zone_name, hide_address, gdpr_agreement_accepted` (пропуск → 400 «Explicit … choices required»). С `gdpr_agreement_accepted:true` AppMetrica ответил 400, причина не раскрыта; после неудачи сверяй список (число записей) и не повторяй вслепую.
- AdMob создание: `POST /api/admob/provision` тело `{projectId, platform:'android', name, storeId:<package>, linkToStore:false}` (форма из клиента панели). 2026-10-13 дало 502 из-за серверного Playwright-воркера (`Add an app` не найден) — чинит оператор, из клиента не обходится. Ad units: `POST /api/admob/provision/ad-units` `{projectId, appId, name, adFormat:'REWARDED|INTERSTITIAL|BANNER'}`.
- AppMetrica `POST /api/appmetrica/applications` с `gdpr_agreement_accepted` и true, и false даёт один и тот же 502 «HTTP 400» — причина не в GDPR; панель не отдаёт тело ответа AppMetrica (`/api/provisioning/health` AppMetrica не покрывает). Нужен лог оператора.
