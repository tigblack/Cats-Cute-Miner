# Панель Multicast

Основной UI: **https://dostupai.aimulticast.org/**, проверен 13.10.2026. Вход — корпоративный аккаунт **текущего сотрудника** из предоставленного доступа. Исторический `https://dostupai-mur.up.railway.app/generator%5C` не является автоматическим fallback или поводом переслать ему ключ другого сервера. У каждого пользователя свои credentials; выбирай существующую сессию/конфигурацию, сверяй доступные записи этой игры и продолжай в его аккаунте. При отсутствии MCP используй browser workflow; его ключ не требуется для штатного UI login.

Панель — административная прослойка над сервисами/сетями: используй её для поддерживаемых операций создания и настройки. Скачиваний SDK/адаптеров в ней нет. Не повторяй в оригинальном кабинете уже рабочую операцию панели. Когда нужной операции или upstream доступа нет, сам запроси конкретный доступ по [service-access.md](service-access.md); MAX и Meta остаются только в панели, для AppMetrica/Adjust возможен прямой кабинет; не поручай создание приложения владельцу. Независимую часть продолжай, настройки сетей наугад не меняй.

Для доступного MCP сначала прочитай [superleo.md](superleo.md): клиент и операции включены в этот же пакет, отдельный скилл не нужен. Перед browser-only регистрацией прочитай [panel-preflight.md](panel-preflight.md): там зафиксированы реально проверенные read-маршруты, формы данных и ошибки доступа пробного запуска. Они позволяют отличить работающую сессию панели от недоступного upstream сервиса.

## Подтверждённый маршрут

1. Открой браузером preview/Playwright или эквивалентом. На форме Email Address / Access Studio используй корпоративный email текущего пользователя из его подключения и штатный вход. При Google login/2FA пользователь завершает вход в браузере; пароль/OTP не сохраняй.
2. `Монетизация Ads` → `/monetization`: список блоков, фильтры приложения/типа, `Add App`, `Обновить`, `Создать`.
3. `Add App` открывает **Платформа → Store ID → Adjust → Итог**. Выбирай Android, сверяй package name игры. Проверь существующие записи: некоторые проекты панели без package name, одного названия недостаточно.
4. `Создать` ad unit: выбор приложения и **Rewarded / Interstitial / Banner**. Заполняй по фактической форме; перечитай результат, сохрани ID/format/package/platform. Несколько placements могут использовать один блок одного формата при соответствующей монетизации; количество кнопок игры не требует отдельного блока для каждой.
5. Кнопка с `title="Редактировать"` в строке открывает настройки. Осматривай форму до записи; отдельную кнопку изменения статуса не используй ради просмотра.

Именование бери из правил студии. Если их нет, понятный вариант — `<game>_Android_<Rewarded|Interstitial|Banner>`. Чужие ID не переносить, сверяй формат/приложение/платформу.

При просмотре существующего блока были предупреждения о ненастроенных AdMob/Pangle credentials и отсутствии Unity Monetize Project ID для автоматического создания placement. Это состояние аккаунта на момент проверки, не универсальное ограничение панели. При таких предупреждениях запиши требуемое подключение конкретной сети; подставленный по соглашению placement ID не доказывает существование блока в сети. Не отмечай все сети готовыми только по наличию MAX ad unit. Если недостающая сеть обязательна для принятой конфигурации, запроси настройку владельца; если набор ещё выбирается, предложи работающий набор с явным указанием отличия.

## Адаптеры

Определи набор сетей/ID через панель, затем проверь соответствующие SDK/адаптеры в проекте. Недостающие готовые пакеты скачивай из официальных источников под текущий движок/Android. Сохрани версии/источник/формат и проверь совместимость MAX/native dependencies. Unity `.unitypackage` не устанавливается напрямую в Godot/web wrapper: выбирай подходящий native adapter/engine plugin или напиши свой мост по архитектуре проекта. Выбор готовой/своей реализации агент принимает сам; критерии находятся в [engines.md](engines.md).

SDK/бинарники загружай на build-машине. В MultiCode часть бинарников не синхронизируется: проверяй ПК, не создавай дубль из-за отсутствия на сервере. Проверяй настройки выбранных сетей через Mediation Debugger/Android build.

## IAP и кабинеты

`Монетизация IAP` → `/monetization-iap` на 2026-10-08: **«Игровой бэкенд не настроен»**, нет Domain/ключа Multicast game backend. UI указывает `Admin → API & Integration → Game Backend`. `Документация` (`/instructions`) была пустой.

Основной маршрут инапов по заданию — **Google Play Console** после согласования. Не меняй глобальные backend-настройки панели ради одной игры, если задача решается напрямую. Если реализация зависит от Multicast backend, запроси точный недостающий доступ и продолжай независимую часть.

Для операций через панель проверяй её реальные возможности и права, не требуя отдельного входа в оригинальный кабинет без необходимости. Google Play Console остаётся маршрутом выпуска/инапов по заданию. При документированном API панели можно автоматизировать вместо UI после проверки фактических методов и результатов. Не выдумывай endpoints/auth/payload.

В `Настройки` (`/settings`) основного UI 13.10.2026 раздел **API и MCP-доступ** показывал `https://dostupai.aimulticast.org/mcp` и персональный Bearer token как способ подключения. Он прямо сообщает: «Для выпуска или перевыпуска ключа обратитесь к администратору». У проверенного аккаунта отдельного пункта Admin не было; generic **API Keys → Manage** disabled/Coming Soon. Не направляй сотрудника в Admin → Users → API/MCP и не обещай самостоятельную выдачу в Settings. Если MCP уже предоставлен, изучи реальные tools и используй подходящие. Если его нет, продолжай доступный UI workflow; запроси конкретное подключение у оператора только для недоступной операции. Не считай один email API-авторизацией. Токен передаётся штатным безопасным механизмом подключения и не входит в пакет скилла. Инсталляцию MCP в MultiCode выполняй штатными интеграционными tools, когда она входит в поручение, без ручной правки агентских конфигов.
