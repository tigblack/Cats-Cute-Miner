# agentb

Одна команда на хабе — свежий Chrome с сохранёнными сессиями, сценарий, компактный JSON, закрытие браузера.
Тулза входит в скилл: `~/.agents/skills/google-play-publish/tools/agent-browser`. Справка: `references/browser.md` установленного скилла.

Зависимости: Node.js 20+ и `npm ci` в папке тулзы отдельно на ПК и на хабе. Одинаковый пакет скилла должен быть установлен на обеих машинах; для передачи используется мост `on-remote --pc-home`. Нужен Chrome на обеих машинах.
На ПК `node agentb.mjs install` проверяет штатное подключение Chrome 144+ (remote debugging должен быть включён).
Расширение и Chrome Web Store не нужны; проверка не меняет реестр и не перезапускает браузер.

На хабе: `/usr/bin/node agentb.mjs login-hub play,adjust,appmetrica,superleo --wait 900`.
Первый вход в рабочей сессии владелец подтверждает штатным запросом Chrome. Повторный `login-hub` использует локальный кэш и не обращается к ПК; `--refresh` явно запрашивает новую передачу только выбранных кабинетов. Только выбранные сессии передаются через SSH на хаб;
команда выводит счётчики и статусы, а не cookies. Дальше `inspect`, `text`, `run`, `upload` работают локально на хабе.
Отказ отменяет передачу. Внутренняя `_transfer-sessions` предназначена только для дочернего процесса, её stdout секретный.

Сессии: `~/.local/share/AgentBrowser/sessions/<ID>/` на хабе, отдельно для текущего чата (`CODEX_THREAD_ID`, вне Codex — `AGENTB_SESSION_ID` либо `--session ID`). Временные копии на ПК удаляются после передачи. Обновлённые cookies и хранилища сохраняются после успешного сценария.
Их нельзя включать в архив тулзы или выводить в чат. Перенесённый вход проверяется отдельно для каждого кабинета.

MAX и Meta используются только через панель Multicast/SuperLeo, прямые сессии этих сервисов не запрашиваются.

`session-clear` удаляет входы текущего чата. Кэш ограничен 8 часами: истёкшие копии удаляются при следующем запуске CLI. Закрытие окна чата само по себе не вызывает CLI; явное завершение работы требует `session-clear`.
