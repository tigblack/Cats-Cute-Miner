# Браузер: agentb

Все браузерные действия (Play Console, Adjust, AppMetrica, панель Multicast/SuperLeo) идут через CLI **agentb** на хабе. Chrome владельца нужен только для разовой передачи сессий после его согласия. MCP-браузеры (`chrome-devtools`, `play-browser`) не используй: они держат долгую сессию через мост и рвутся. Серверный воркер SuperLeo `play_*` — только если agentb недоступен ([superleo-play.md](superleo-play.md)).

MAX и Meta доступны через панель Multicast/SuperLeo: прямые страницы и перенос их сессий не используются.

## Где и как вызывать

Тулза входит в скилл: `<skill>/tools/agent-browser`, где `<skill>` — `~/.agents/skills/google-play-publish` (на Windows `%USERPROFILE%\.agents\skills\google-play-publish`). Далее `<agentb>` — эта папка. Установи одинаковый пакет на хабе и ПК. Из любого проекта:

```text
/usr/bin/node <agentb>/agentb.mjs <команда> ...
```

Каждый вызов: свежий headless Chrome с сохранёнными сессиями → одно действие или сценарий → один JSON в stdout → браузер закрыт. Вкладки не копятся, общей сессии нет. После обрыва запись могла сохраниться на сайте: сначала readback, затем решение о повторе. Ответ всегда `{"ok": true, ...}` либо `{"ok": false, "error", "url", "shot"}`.

## Рабочая сессия без повторных разрешений

- Сначала `sessions`: готовые входы текущего чата переиспользуются во всех сценариях и следующих сообщениях. Перезапуск Chrome между вызовами не требует повторного подключения к ПК.
- `login-hub` запрашивает только отсутствующие входы. Если все выбранные входы сохранены, он возвращает `reused` без SSH, отладки и открытия страниц. Не делай перенос заново для проверки доступа, нового действия, ответа пользователя или ошибки сервера.
- `AUTH_REQUIRED` после реального возврата на экран входа — повод для `login-hub <один кабинет> --refresh`. HTTP 5xx, таймаут, недоступность AppMetrica или ошибка селектора не являются поводом снова тревожить владельца. По одному факту наличия кэша рабочую авторизацию не утверждай: читай нужную страницу.
- Кэш изолирован ID чата (`CODEX_THREAD_ID`; для другого клиента задай стабильный `AGENTB_SESSION_ID` либо один `--session ID` на весь рабочий сценарий). Другой чат автоматически его не подхватывает. Успешные сценарии сохраняют обновлённые cookies/localStorage/sessionStorage; токены не теряются при закрытии временного Chrome.
- По явному завершению рабочей сессии вызови `session-clear`. Не очищай входы после каждого ответа модели: это снова потребует согласие на следующем сообщении. Максимальный срок копии — 8 часов; при следующем вызове CLI истёкшие файлы удаляются. У CLI нет события закрытия чата: без следующего вызова/явной очистки файлы остаются на диске, но просроченный кэш не используется.

## Настройка и передача входа

- Зависимости `npm ci` установлены отдельно на ПК и хабе; Node.js 20+. На хабе используй настоящий локальный Node (`/usr/bin/node`), а не `node` shim, который перенаправляет команду на ПК. Нужен локальный Chrome.
- Проверка на ПК: `on-remote --pc-home node .agents/skills/google-play-publish/tools/agent-browser/agentb.mjs install`. Она проверяет наличие штатного endpoint Chrome 144+; `ready` не означает успешную передачу или вход в кабинет. Расширение, Chrome Web Store, CRX и политики реестра этому маршруту не нужны.
- Передача с хаба: `/usr/bin/node <agentb>/agentb.mjs login-hub play,adjust,appmetrica,superleo --wait 900`. Chrome на ПК сам показывает запрос «Разрешить» ([штатный механизм Chrome](https://developer.chrome.com/blog/chrome-devtools-mcp-debug-your-browser-session)). Агент не подтверждает его за владельца. После согласия короткое локальное подключение получает cookies, localStorage и sessionStorage **только выбранных сайтов**, закрывает созданные им временные вкладки и отключается от Chrome владельца. Его прежние вкладки остаются открыты.
- Данные идут на хаб по существующему SSH-каналу, без вывода cookies в ответ инструмента. Для этого workflow пользователь явно разрешил перенос сессий на хаб. При отказе новая передача не использует старые сессии. Внутреннюю `_transfer-sessions` отдельно не вызывай: её stdout содержит секреты и предназначен только дочернему процессу `login-hub`.
- Сессии хаба: `~/.local/share/AgentBrowser/sessions/<ID>/`; временная копия на ПК: `%LOCALAPPDATA%\AgentBrowser\sessions/<ID>/`, удаляется после передачи. Не выводи их содержимое в чат, не добавляй в проект/архив. На Linux файлы создаются с правами 0600.
- sessionStorage восстанавливается до загрузки страницы только для точного origin: панель Multicast хранит там вход. Одних cookies/localStorage для неё недостаточно.
- `sessions --check` показывает сохранённые сессии и предварительную доступность страниц. HTTP-ошибка, экран входа или отсутствие перенаправления не доказывают успешный вход. Подтверди нужный аккаунт и доступ к реальным данным кабинета через `inspect`/`text`. Серверный сбой AppMetrica — `waiting`, остальные кабинеты проверяй независимо.
- Перенос не гарантирует принятие сессии Google или другого сервиса. Проверяй каждый кабинет на хабе; не переключайся молча на управление браузером владельца. Ошибка аутентификации требует разбора/обновления конкретного входа, а не слепых повторов записи.
- `login-window` — отдельный запасной маршрут с ручным входом, применим только если владелец согласовал такое отклонение от требования «одна кнопка».

## Команды

| Команда | Зачем |
| --- | --- |
| `inspect --url URL` | Вместо скриншота: заголовки, кнопки (`[disabled]`), поля со значениями, радио/чекбоксы `[x]`, диалоги. |
| `text --url URL [--selector CSS] [--max N]` | Текст страницы или блока: статусы, таблицы, readback. |
| `run FILE.json --set base=URL_ПРИЛОЖЕНИЯ` | Форма Console по профилю `scenarios/profiles/*.json` через `scenarios/console_run.js`: все шаги + readback одним вызовом. |
| `run FILE.js --url URL [--set-file K=файл]` | Готовый скрипт страницы, `__K__` заменяется содержимым файла (JSON). |
| `run FILE.mjs [--url URL] [--set K=V]` | Многошаговый сценарий Playwright: несколько страниц, загрузки, диалоги. |
| `upload --url URL --file ПУТЬ_НА_ПК [--chooser "Upload" \| --input CSS] [--wait-text T] [--click Save]` | AAB/картинки без диалога; ждёт текст обработки и жмёт кнопки. |

Общие флаги: `--show` (видимое окно, для отладки при владельце), `--timeout MS` (действие, по умолчанию 15000), `--service a,b` (какие сессии подгрузить; по умолчанию все сохранённые).

Готовые сценарии в `<agentb>/scenarios`: `console_run.js` + `profiles/*.json` (Ads, Ad ID, Government, Finance, Health, Data safety шаг 2), `data_safety_dialogs.js` (`PLAN`: `[["строка типа", "секция", ["App functionality", "Analytics", ...]], ...]`, метки целей полностью), `adjust_events_create.js` (`NAMES`: массив имён, до 25 за вызов), `adjust_events_read.js`.

## Правила

- **Смотри страницу через `inspect`/`text`.** Скриншот нужен только при сбое (`shot` — локальный PNG на хабе).
- **Контекст живёт один вызов.** Всё, что не сохраняется на сервере между шагами (мастер, диалог, несохранённая форма), делай одним `.mjs`. Свой сценарий пиши в `<agentb>/scenarios/tmp/` на хабе и сразу запускай `run scenarios/tmp/<файл>`: сценарий выполняется локально, синк на ПК не нужен. JSON-значения передавай `--set-file` из той же папки: это исключает сложное shell quoting.
- **Сценарий `.mjs`:** `export default async ({ page, args, settle, inspect }) => result`. Локаторы по роли и тексту (`page.getByRole('button', { name: 'Save' })`), после действия `await settle()`, в конце верни readback, а не «ok».
- URL Console с `?hl=en`: профили и сценарии рассчитаны на английский интерфейс.
- После сбоя записи сначала readback (`inspect`/`text`) по устойчивому признаку (package, versionCode, статус), без слепого повтора Save/Submit/Publish.
- Файлы (AAB, графика) — абсолютные пути на хабе; после загрузки сверь `bytes` и статус обработки.
- Длинную обработку Google не жди в одном вызове: короткие повторные `text` с интервалом.

Пример `.mjs` (выпуск internal уже загруженного драфта):

```js
export default async ({ page, args, settle, inspect }) => {
  await page.goto(`${args.base}/tracks/internal-testing?hl=en`);
  await settle();
  await page.getByRole('button', { name: /Edit release/ }).click();
  await settle();
  await page.getByRole('button', { name: 'Next' }).click();
  await settle();
  await page.getByRole('button', { name: /Save and publish/ }).click();
  await settle();
  return inspect();
};
```
