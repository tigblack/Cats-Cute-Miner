# Запрос доступов и создание приложений сервисов

Владелец предоставляет доступы; агент проверяет их, создаёт нужные приложения, получает собственные SDK-настройки, внедряет и проверяет интеграцию. Этот сценарий входит в «давай в стор». Не заменяй его предложением владельцу самостоятельно завести AppMetrica/Adjust и прислать ключи. Использование существующего приложения допустимо после проверки его принадлежности этой игре.

## Сначала проверить, затем запросить

На новом ПК другого сотрудника нет private файлов и сессий предыдущего владельца. Основная панель — https://dostupai.aimulticast.org/ (явно предоставленный endpoint имеет приоритет). При отсутствии MCP открой одну вкладку и попроси обычный вход текущего сотрудника; не требуй `SUPERLEO_API_KEY`, путь к репозиторию другого ПК и отдельные credentials всех сервисов одним предварительным условием. Если email ещё не сообщён, запроси только его либо предложи завершить вход в открытой вкладке. Используй предоставленный сотруднику аккаунт; не подставляй почту прежнего владельца. Затем инспектируй реальные доступные формы и права операций. Вход не гарантирует upstream permissions: конкретный 401/403, отсутствующая функция или ненастроенный provider оформляются отдельным запросом после проверки.

На 13.10.2026 проверенная `/settings` показывала **API и MCP-доступ** и текст обращения к администратору для выпуска ключа. Видимого меню Admin и самостоятельной выдачи ключа у проверенного аккаунта не было; generic **API Keys → Manage** disabled. Не предписывай пользователю искать Admin → Users → API/MCP. Если MCP всё же нужен, запроси уже выданное персональное подключение либо выпуск у ответственного оператора; пока доступен UI, работа через него продолжается. Пути UI проверяются заново в роли текущего сотрудника.

1. Прочитай текущее состояние и ранее данные доступы: project secrets, explicit private config, подключённые MCP и доступные браузерные сессии. Не запрашивай повторно работающий доступ. Пользователь каждого запуска использует свой корпоративный аккаунт; предыдущая почта и личные ключи не являются defaults.
2. Проверь identity/организацию, чтение приложений и права нужной операции. Отдельно оцени создание, настройку, чтение SDK credentials и просмотр результатов SDK. SDK key или app token подтверждает конфигурацию клиента, но не право создавать приложения.
3. Сначала используй панель для поддерживаемых действий. Если операция отсутствует, провайдер вернул401/403 либо служба не настроена, сформулируй конкретный недостающий доступ. Для AppMetrica/Adjust допустим официальный API/кабинет под предоставленным пользователем аккаунтом. MAX и Meta обслуживаются только через панель Multicast/SuperLeo; их прямые кабинеты и логины не запрашиваются. Наличие входа в панель не гарантирует доступы её upstream сервисов.
4. Запроси сразу известные недостающие доступы коротким списком: сервис, нужная операция/право и один подходящий способ предоставить доступ. Не отправляй владельца выполнять регистрацию приложений. Пользователь может дать отдельные подключения по мере готовности; каждый ответ обрабатывай сразу, независимую работу продолжай.
5. После ответа проверь именно выбранное подключение и возобнови ожидающую операцию. Фраза «я вошёл» и наличие secret-файла не доказывают рабочий доступ из браузера агента. При недостаточной роли запроси нужное право; при поломке backend запроси восстановление конкретной службы, а не тот же пароль снова.

Пример запроса после проверки, если этих доступов действительно нет:

> Для создания приложений не хватает двух доступов: AppMetrica — доступ к управлению приложениями; Adjust — аккаунт с правом добавлять приложения. Можно войти в открытые мной кабинеты либо сохранить подходящие API credentials в локальном secret-файле и указать его путь. После входа/подключения приложения и SDK-настройки заведу сам.

Предпочитай штатное окно входа/OAuth или private config проекта. Пароли и2FA пользователь вводит в браузере. Не проси полный профиль Chrome или копию всех паролей. Для уже разрешённого подключения/переноса сессий используй [panel-preflight.md](panel-preflight.md); сохраняй только нужные сервисы. Запись необходимых локальных credentials входит в предоставление доступа этому workflow; для долговременного экспорта browser session state нужно явное поручение пользователя.

## Какие доступы нужны

| Сервис | Что запросить при отсутствии | Что делает агент после проверки |
| --- | --- | --- |
| Панель | Личное MCP-подключение или вход текущего пользователя с правами проекта | Читает catalog/capabilities, находит/создаёт карточку игры и использует реальные операции |
| AppMetrica | Рабочий доступ панели; иначе OAuth управления с appmetrica:read/write либо вход в кабинет с правом добавления приложений | Находит/создаёт приложение, перечитывает numeric ID и получает собственный SDK key |
| Adjust | Рабочая операция панели; иначе доступ App Automation API с включённой функцией/подходящим template либо вход AppView с правом создания | Находит/создаёт приложение, настраивает Android/Google Play package, получает app/event tokens |
| Meta | Рабочая provision-служба панели Multicast/SuperLeo; при сбое нужен доступ/ремонт этой службы | Создаёт/переиспользует app, получает ID/client token, сохраняет Android-настройки |
| MAX и сети | Доступ панели к MAX и нужным сетям; конкретное отсутствующее provider credential/право | Создаёт приложения и placements, связывает форматы MAX, перечитывает настройки |
| Google Play | Console-подключение с правами этой игры: настройка, IAP и internal release; отдельно доступный worker/staging | Создаёт страницу, товары, доставляет release AAB и выпускает в разрешённый трек |

Запрашивай только строки, для которых проверка выявила реальный пробел. Не требуй прямого входа в каждый сервис, если рабочее подключение панели покрывает все нужные операции. При ошибке одного сервиса не объявляй остальные доступы отсутствующими. Вход в Play не заменяет Java/bundletool и доставку AAB на browser host.

## AppMetrica: создание и собственная конфигурация

Предпочитай операции действующего catalog панели по [superleo.md](superleo.md). Прямой API управления требует OAuth; UUID SDK key к этому доступу не относится. Официальная [авторизация](https://appmetrica.yandex.com/docs/ru/mobile-api/intro/authorization) описывает права appmetrica:read и appmetrica:write. Credentials читаются из private config и передаются заголовком, не URL или аргументом командной строки.

Сначала прочитай доступные приложения и проверь карточку по данным игры; AppMetrica Management create не содержит package field, поэтому одинакового названия недостаточно для автоматического выбора неоднозначной записи. Для нового приложения используй фактическую category, reporting timezone и уже выбранные privacy/legal настройки. Реальный маршрут описан в [создании приложения](https://appmetrica.yandex.com/docs/ru/mobile-api/management/applications/createapplication). Не подставляй gdpr_agreement_accepted=true без принятого обязательства; неизвестное заявление согласовывается отдельно от доступа.

После создания сохрани numeric id и SDK key api_key128 по назначению, перечитай карточку и сравни с runtime config. Не копируй management OAuth/import token в SDK config. При таймауте сначала найди результат; не создавай дубль. Доступ, создание, активация SDK и получение игровых/ad-revenue событий имеют отдельные доказательства.

## Adjust: API либо AppView

Проверь рабочую операцию панели, затем выбранный прямой маршрут. [App Automation API](https://dev.adjust.com/en/api/app-automation-api/) требует включённую функцию аккаунта, подходящий template и Adjust API token. SDK app token и tracker/link token — разные значения, они не заменяют этот доступ. API список может не показывать созданные только через Dashboard приложения: проверь также AppView/доступные settings существующих кандидатов до создания.

Перед использованием template проверь его организацию и переносимые настройки; это может копировать события/партнёров/callbacks. Не запускай миграцию существующего приложения только ради проверки подключения. Для новой Android app реальные name/bundle_id/store_id/platform берутся из игры; контракт — [App endpoint](https://dev.adjust.com/en/api/app-automation-api/app-endpoint/). Ticket означает фоновую операцию: дождись фактического результата и перечитай настройки. Не используй force_update для обхода неясного результата.

Если функция API недоступна, запроси вход в официальный AppView с правом добавлять приложения. Маршрут — All apps → New app, затем Android/Google Play и точный package по текущей форме. Reporting currency берётся из студийных настроек аккаунта/проекта; если неизвестна, уточни до создания, поскольку она не меняется. Сведения о роли/создании — [AppView app token and reporting currency](https://help.adjust.com/en/article/app-token-and-reporting-currency). Получи собственный SDK app token и только нужные event tokens, подключи sandbox для QA и production для release по основному контракту. Не выдавай новую app за проверенную доставку session/ILRD.

Создание через AppView проверено 2026-10-09: сначала поиск приложения, затем New app → name/currency → Add app → Add platform → Android → Google Play Store → App ID = точный package → Apply → Save. Дождись сообщения `Platform changes saved` и перечитай сохранённый package. SDK integration показывает App name, Reporting currency и **App token**: сравни их с созданной записью и запиши token private. Вкладки могут иметь вложенный кликабельный элемент: проверяй фактическую смену URL/title и содержимого, одного selected-состояния внешней кнопки недостаточно. Пустой список Events допустим, если контракт проекта использует только sessions/attribution и специальный ad revenue API; custom events требуют собственных tokens новой app.

## Состояние и возобновление

В profile.service_access.checks сохраняй по сервису route, status, account_ref, target_operation, required_permissions, checked_at, safe evidence_ref и secret_ref. Последнее — ссылка, не значение credential. Статусы: not_checked, ready, waiting_for_access, insufficient_permissions, service_unavailable. ready здесь означает доступ к операции, а не готовую интеграцию.

В service_access.pending_requests сохраняй service/operation, точный недостающий доступ, requested_at, текст запроса и следующий шаг. При наличии незакрытого запроса не задавай тот же вопрос повторно без новой причины; отмечай полученную часть и задавай только остаток. Если запущен async запрос, продолжай независимые этапы и сохраняй его для следующего сообщения пользователя. Не считай молчание предоставленным доступом. Полученный доступ закрывает запрос лишь после проверки и продолжения нужного шага.

Для каждого приложения различай reused/created, реальные IDs, create/readback evidence, private SDK config ref, integration и device/dashboard verification. Предыдущее подключение Piggy Payday к существующим AppMetrica/Adjust не доказывает создание новой app. В отчёте о проверке скилла разделяй инструкции сценария и реально пройденные операции; не создавай фиктивные production apps ради заявления «протестировано».
